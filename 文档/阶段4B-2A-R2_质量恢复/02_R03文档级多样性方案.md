# R03 文档级多样性方案

## 方案对比

| 方案 | 真实表现 | 决策 |
|---|---|---|
| Dify Chat 节点 Top K 3 → 12 / 10 | 应用配置已发布到 `#13/#14`，但 Chat API 的 `retriever_resources` 仍只返回 3 条 | 否决，不能据此宣称扩池 |
| 仅按首个文档去重 | 仍可能由退货、FAQ、保修标题占据三席 | 否决，不能稳定覆盖渠道 |
| Dify Dataset Retrieve → 逻辑文档去重 → Top3 | 内部候选池 12–14 条，输出 3 个不同文档；R03 覆盖退货与渠道 | 采用 |

## 采用的通用链路

1. 从正式问题与改写问法构建通用检索子查询；
2. 选择信息量最大的代表问法，并追加请求中已有的购买渠道上下文；
3. 调用真实 Dify Dataset Retrieve，使用：
   - Hybrid Search；
   - `qwen3-rerank`；
   - 向量权重 0.7、关键词权重 0.3；
   - 请求内部候选池 `top_k=10`；
4. 对返回结果按逻辑 `doc_id` 去重，并在不同文档间轮询择优；
5. 只把最终 3 条不同文档切片加入生成上下文；
6. BFF 再执行一次 segment 唯一性校验，向用户只展示最终 Top3。

该链路不包含 POC-R03 关键词、文档编号或问题模板硬编码。正式任务中的
`channel`、原始问题与改写问法都来自已冻结输入。
