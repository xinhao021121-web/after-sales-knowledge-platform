# 十五条交互演示脚本

日期：2026-10-24
入口：[index.html](index.html)
演示控制：点击顶部“演示脚本 15”，载入任一场景。

## D01 新建 ASQ 并生成上下文任务

1. 以一线客服打开 D01；
2. 在 P02 点击“新建咨询”；
3. 系统创建 `ASQ-2026-1060`，进入 P03 的 `ASQ_CONTEXT_PENDING`；
4. 确认页面只有一个 ASQ 主状态，且 ADV 显示“建议草案不可发送”；
5. 点击“补齐检测结果”，验证 `C2→C3` 后先进入 `ASQ_ASSESSING`；
6. 点击“生成处理建议”，验证进入 `ASQ_ADVICE_PENDING`，再出现发送动作。

## D02 补齐 CTX 并展示版本差异

1. 载入 D02；
2. 在 P03 点击“补齐检测结果”；
3. CTX 从 v3 升至 v4，完整度从 `C2` 变为 `C3`；
4. 验证任务主状态先进入 `ASQ_ASSESSING`，不直接跳到建议待确认；
5. 点击“生成处理建议”后进入 `ASQ_ADVICE_PENDING`；
6. 刷新页面，CTX 版本与 ASQ 状态均保持。

## D03 证据不足、冲突和承诺拦截

1. 载入 D03；
2. 点击“模拟证据不足”，验证 `C2`、缺失字段和 `ASQ_CONTEXT_PENDING`，且无发送按钮；
3. 点击“模拟证据冲突”，页面保留冲突双方并暂停承诺；
4. 补齐 CTX 后进入 `ASQ_ASSESSING`，再生成建议进入 `ASQ_ADVICE_PENDING`；
5. 勾选“插入越权文案”，点击“确认并发送建议”；
6. 系统以行内结果阻断，ASQ 保持 `ASQ_ADVICE_PENDING`，不改变为已答复。

## D04 ADV 确认发送

1. 载入 D04，当前角色为主管；
2. 检查 CTX 区域只读且无编辑按钮；
3. 点击“确认并发送建议”；
4. ADV 绑定 CTX/EVD，ASQ 进入“已答复 / ASQ_RESPONDED”；
5. 刷新后发送状态保持。

## D05 R3 止损、升级、关闭和 ESC 复发新单

1. 载入 D05，当前角色为法务/安全责任人；
2. 点击“发送止损指令”，风险仍保持 R3；
3. 点击“升级安全责任人”；
4. 点击“关闭风险单”，旧单进入 `ESC_CLOSED`；
5. 点击“演示风险复发”，创建新 ESC_CANDIDATE，并以 `previous_esc_id` 指向旧单。

## D06 SRC 登记、激活、失效与替代

1. 载入 D06，点击“登记新来源”并填写标题、URL/文件、组织、范围、有效期、责任人和核验日期；
2. 暂时不确认标题核验，登记后点击“尝试激活来源”，验证保持 `SRC_REVIEW_REQUIRED`；
3. 重新打开表单确认可访问与标题核验后再次登记，激活进入 `SRC_ACTIVE`；
4. 点击“模拟来源撤回”，检查 SRC、KB、EVAL、REL、LINK、CASE 的影响清单；
5. 查看替代来源并创建新版本，验证新来源为 `SRC_REGISTERED` 且保留 `previous_source_id`。

## D07 CASE 创建、分诊和 0/1/N LINK

1. 载入 D07，在 P08 创建模拟 CASE；
2. P09 显示 0 LINK 和 `CASE_OPEN`；
3. 点击分诊，CASE 进入 `CASE_TRIAGED`；
4. 添加第 1 条 LINK，形成单轨修复；
5. 再添加后续 LINK，形成 N 条并行知识条目轨道。

## D08 部分 LINK 完成时禁止关闭

1. 载入 D08，打开 P09；
2. 点击“尝试关闭 CASE”；
3. 页面内显示活动 LINK 数量和最新失败轨道；
4. CASE 保持 `CASE_FIXING`；
5. 关闭按钮不能制造成功状态。

## D09 LINK_FAILED 创建后继

1. 载入 D09；
2. 在失败轨道点击“创建后继”；
3. 新建 `LINK_OPEN`；
4. 新 LINK 的 `previous_link_id` 指向失败 LINK；
5. 原失败证据只读保留。

## D10 EVAL 状态机与结果联动

1. 载入 D10，以 AI 评测人员进入 P10；
2. 验证 `EVAL_PLANNED` 不显示结果动作；尝试直接产生结果应被拒绝并留下非法转换审计；
3. 点击“开始评测”，验证进入 `EVAL_RUNNING`；此时可“中止并回 EVAL_PLANNED”；
4. 再次开始后生成通过结果，验证 EVAL、KB、REL、LINK、CASE 五类对象同步更新；
5. 分别重载 D10 验证失败和阻塞：失败联动 `KB_EVAL_FAILED`、`REL_REJECTED`、`LINK_FAILED`、`CASE_FIXING`；阻塞联动 `EVAL_BLOCKED`、`REL_SUSPENDED`、`CASE_FIXING`。

## D11 REL 拒绝回退

1. 载入 D11，以主管进入 P11；
2. 点击“拒绝发布”；
3. REL 进入 `REL_REJECTED`；
4. 匹配 LINK 进入 `LINK_FAILED`；
5. CASE 回到 `CASE_FIXING`，不残留待发布状态。

## D12 REL 发布、LINK 释放和 CASE 聚合关闭

1. 载入 D12，场景预置其他知识条目已完成；
2. 点击“批准并激活”；
3. REL 进入 `REL_ACTIVE`；
4. 待发布 LINK 变为 `LINK_RELEASED`；
5. 全部知识条目最新 LINK 完成后，CASE 进入 `CASE_CLOSED`。

## D13 REL 停用、回滚和后继 LINK

1. 载入 D13，以知识运营打开 P11；
2. 停用当前 REL；
3. 创建回滚候选并切换主管；
4. 主管激活回滚候选；
5. 历史 LINK 不变，新增后继 LINK_OPEN，CASE 进入 `CASE_REOPENED`。

## D14 无 LINK CASE 双角色审批关闭

1. 载入 D14，以主管打开无 LINK CASE；
2. 点击主管批准；
3. 切换业务/渠道负责人，点击业务批准；
4. 两名不同角色批准齐全后 CASE 才关闭；
5. 单一批准时保持 `CASE_FIXING`。

## D15 角色切换与权限拒绝

1. 载入 D15，业务/渠道负责人直接访问 P03；
2. 系统显示“无法访问此页面”；
3. 不展示客户、CTX、EVD 或 ADV；
4. 切换系统管理员进入 P12，查看成员/活动角色并成功变更一名成员的技术角色；
5. 分别尝试自审自批、管理员发布和普通角色关闭 R3，验证对象状态不变且审计出现拒绝记录。

## 展示模式验证

1. 在评审模式确认 FR 编号、页面状态注入和 15 条演示脚本可见；
2. 切换“展示模式”，确认 FR、演示入口、技术说明、模拟按钮和页脚技术提示隐藏；
3. 验证产品顶栏只显示“模拟环境”，不出现“生产演练”或“非 Apple 项目”；
4. 切回评审模式后恢复追踪与状态注入能力。

## 演示验收规则

- 每条路径至少改变一个真实对象状态或留下可追踪审计；
- 页面内结果必须说明状态变化、继续动作或阻断原因；
- 刷新浏览器后，角色、页面和关键动作保持；
- 不得以 toast 或静态提示代替对象状态变化。
