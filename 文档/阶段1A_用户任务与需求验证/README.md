# 阶段 1A：用户任务与需求验证

状态：交付完成，待阶段验收  
日期：2026-10-22  
项目性质：公开资料驱动的模拟企业内部项目

## 1. 阶段目标

在不伪造真实访谈、客户数据和业务结果的前提下，用公开售后资料和公开用户问法验证以下需求问题：

- 五类关键角色分别承担哪些任务和判断责任？
- 售后问题从提出到解决或升级，当前有哪些信息断点？
- 哪些规则、例外、渠道和安全条件会影响正确处理动作？
- 如何用可追溯样本和人工标注规则验收模拟方案？

## 3. 边界

本阶段只做需求验证，不做：

- 信息架构；
- PRD；
- 页面或交互原型；
- 状态机与权限矩阵；
- 技术选型参数；
- 阶段 2 工作。

## 4. 验收标准

- 五类角色均有任务、判断、产出、风险和交接；
- 公开问题样本不少于 30 条，且至少覆盖普通规则、条件例外、渠道差异、安全风险、知识缺失和表达模糊六类；
- 每条样本均有公开问法来源、已知/缺失上下文、追问、正确动作、不可接受错误和证据来源；
- 现状旅程含主路径与四类异常分支；
- 规则因子清单能解释“为什么相同问题会产生不同处理动作”；
- 代理指标有可执行的人工标注规则，且不与真实业务指标混淆；
- 不声称真实访谈、真实客户数据或业务结果。
