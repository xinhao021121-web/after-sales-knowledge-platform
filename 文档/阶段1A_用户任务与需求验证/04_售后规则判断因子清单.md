# 售后规则判断因子清单

版本：V0.1  
日期：2026-10-22  
用途：需求验证与样本标注，不是最终业务规则或技术参数

## 1. 原则

一条售后问题能否被正确处理，不由单一关键词决定。系统需要识别多个因子之间的组合关系，并明确哪些事实已知、哪些需要追问、哪些必须升级。

判断顺序应遵循：

1. **先安全，后权益**：存在安全风险时，先停止危险行为并升级；
2. **先身份，后责任**：核验商品、订单、渠道和凭证，避免错误责任归属；
3. **先适用，后回答**：确认规则适用于当前商品、渠道、时间和状态；
4. **先证据，后承诺**：没有有效证据时只给条件性说明；
5. **先授权，后执行**：退换、保修、赔偿等实际行动需符合人工授权边界。

## 2. 核心因子

| 因子 | 需要判断的内容 | 为什么影响处理 | 缺失时的动作 | 主要证据 |
|---|---|---|---|---|
| F1 商品身份 | 品牌、品类、型号、SKU/部件、序列号 | 不同型号的功能、配件、安全和保修边界不同 | 追问或要求照片/系统核验，不猜型号 | O09/O15/O16 |
| F2 销售与履约主体 | 自营、第三方平台店、授权经销、线下门店、其他来源 | 决定退货入口、售后责任和品牌兜底范围 | 标记渠道待核实，停止责任承诺 | O13/O16 |
| F3 购买/签收/服务时间 | 下单、交付、签收、服务事件时间 | 决定法定期间、商业政策期间、保修阶段和历史服务关系 | 用订单、物流、发票或服务单补证 | O02/O03/O10/O11 |
| F4 客户诉求 | 使用帮助、退货、换货、维修、费用、投诉、安全求助 | 决定任务链和需要的证据 | 先区分诉求；“坏了”不能直接映射为退货 | O01/O16 |
| F5 故障表现 | 无声、断连、耗电、发热、进液、外观异常等 | 影响风险等级、排查顺序和服务路径 | 追问具体现象、发生条件和复现方式 | O04/O05/O06/O10/O14 |
| F6 商品与配件状态 | 完好、拆封、损坏、缺失、污染、非原装部件 | 影响退货、保修和质量责任判断 | 要求照片、配件清单和状态说明 | O02/O03/O11/O16 |
| F7 风险等级 | 正常、注意、高风险、紧急 | 高风险必须先止损，不能继续普通规则判断 | 触发安全追问或升级，不等待完整订单信息 | O14/O16 |
| F8 保障与责任类型 | 法定规则、品牌商业政策、三包、有限保修、延保、保外服务、平台售后 | 不同保障可以并存，不能互相替代 | 逐项核对适用性并标明冲突 | O02/O03/O10/O11/O12/O16 |
| F9 适用范围与有效期 | 地区、商品线、渠道、活动、版本、起止日期 | 相同问题在不同范围可能有不同答案 | 标记为不适用/待确认，不使用旧规则 | O01/O02/O11/O16 |
| F10 证据质量 | 官方原文、订单、发票、物流、照片、检测单、工单 | 证据决定能否确认身份、时间和故障 | 明确缺少哪种证据，避免推断 | O01/O10/O13/O16 |
| F11 责任角色 | 一线客服、售后专员、主管、知识运营、业务/渠道、法务或专业支持 | 决定谁有权判断和承诺 | 按未决事项转交，不越权 | O16 |
| F12 用户情绪与紧急程度 | 是否担心安全、是否重复联系、是否投诉或权益争议 | 影响沟通优先级和升级时机 | 优先确认安全和已采取动作 | O14/O16 |
| F13 客户隐私与授权 | 需要哪些信息、是否必要、是否已获授权 | 售后处理不应索取无关敏感信息 | 只收集最少必要信息，提示用途 | O03/O16 |
| F14 答案确定性 | 已知事实是否足够，证据是否冲突，规则是否明确 | 决定直接建议、条件性建议或升级 | 不确定时明确不确定点 | O01/O16 |

## 3. 因子之间的关系

### 3.1 必要条件

以下组合缺失时，不应生成确定性售后结论：

- 商品身份 + 实际渠道 + 关键时间；
- 故障表现 + 商品状态 + 是否安全风险；
- 责任类型 + 适用证据 + 有权处理的角色。

`[判断]` 这些条件来自 30 条公开问题的共同结构，但尚未通过真实客户分布或组织流程验证。

### 3.2 安全优先规则

只要出现以下任一信号，普通规则的优先级下降：

- 冒烟、明火、爆裂声；
- 刺鼻异味或明显熔化；
- 外壳鼓包、变形或液体渗出；
- 异常高温、烫伤或持续皮肤反应；
- 进液后仍尝试充电或出现异常；
- 设备身份高度可疑且涉及安全或权益。

正确处理顺序：停止危险动作 -> 收集最少事实 -> 升级安全/售后/主管 -> 再处理退换修。

### 3.3 时间因子的组合

时间不能单独决定结果。例如：

- `收到商品后 7 日内` 是法定远程交易无理由退货的重要时间条件，但仍需判断交易方式、商品性质和商品完好；
- Apple 官方商店公开写明符合条件商品可在交付后 14 个自然日内申请退货，但这是其商业政策，不能自动适用于所有第三方渠道；
- 保修期、服务次数、历史维修和保障合同可能产生不同关系。

因此，任何时间判断必须同时绑定渠道与保障类型。

### 3.4 渠道因子的组合

渠道至少应拆成：

- 客户从哪里购买；
- 谁负责履约和开票；
- 谁承诺退货或换货；
- 哪个主体提供维修或授权服务；
- 当前证据能否证明这些关系。

只写“京东/拼多多/线下店”不足以判断责任。

### 3.5 冲突处理

当来源、订单、渠道和客户陈述冲突时：

1. 保留冲突证据，不删除不同结论；
2. 标记无法确认的字段；
3. 停止支付、退换、免费维修等不可逆承诺；
4. 按问题类型转业务、渠道、售后或主管；
5. 将冲突作为知识问题登记，而不是强行合并成单一答案。

## 4. 建议的样本标注结构

每条公开问题至少标注：

| 字段 | 取值示例 |
|---|---|
| 主要验证域 | 规则判断 / 安全升级 / 知识闭环 |
| 主要诉求 | 使用指导 / 退货 / 换货 / 维修 / 费用 / 渠道责任 / 安全 |
| 已知因子 | 型号、渠道、时间、状态、风险信号等 |
| 缺失因子 | 尚未提供的必要条件 |
| 追问字段 | 为完成判断必须问的内容 |
| 风险等级 | 常规 / 注意 / 高风险 / 紧急 |
| 建议动作类型 | 直接指导 / 条件性答复 / 补证 / 转售后 / 转主管 / 安全止损 / 知识缺口 |
| 需要证据 | 官方规则、订单、发票、照片、服务单、检测结果等 |
| 不可接受错误 | 越权承诺、漏安全升级、错误渠道、无依据结论等 |
| 标准答案依据 | 官方来源 ID + 业务判断规则 |

## 5. 不应写入本清单的内容

阶段 1A 不定义：

- 检索参数、模型、阈值和排序策略；
- 精确的自动化率；
- 角色权限矩阵；
- 内部审批节点和页面交互；
- 未经客户业务/法务复核的最终售后口径。

这些内容必须在后续阶段基于真实业务流程或明确模拟规则继续验证。
