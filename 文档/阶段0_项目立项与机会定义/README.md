# 阶段 0：项目立项与机会定义

文档状态：阶段 0 有条件通过，已于 2026-10-22 按导师意见完成修订  
创建日期：2026-10-22  
适用阶段：企业级 RAG 知识库平台从 0 到 1 立项

## 项目性质

本项目正式定义为**公开资料驱动的模拟企业内部项目**。

- 不进行或伪造真实客户访谈；
- 不使用虚构内容冒充真实客服对话、订单、工单或业务结果；
- 公开问题样本只代表公开表达，不代表目标客户的实际问题分布；
- 业务北极星指标保留为未来真实项目的方向，模拟阶段用可审计的代理指标验收；
- 所有产品判断、模拟标注和假设均明确标注来源与证据等级。

## 本阶段结论

电商售后服务可以作为首个验证场景，但必须收窄为“多渠道消费电子品牌的售后知识运营与坐席辅助”，而不是泛化的企业文档问答或全自动客服。

公开资料显示，同一售后诉求会同时受到法定规则、品牌商业政策、销售渠道、商品状态、购买时间和安全风险的影响。通用 RAG 产品已经较充分地覆盖文档解析、检索、引用、工作流和 Agent 编排，因此本项目的判断不能建立在“支持 RAG”上。更值得验证的差异点是：

- 答案必须理解渠道、商品、时间和风险等业务上下文；
- 回答必须可追溯到有效知识，而不是只给出相似片段；
- 高风险问题必须先止损和升级，不能由模型自由承诺；
- 知识发布、失效、回滚和失败案例必须形成运营闭环；
- 产品价值必须用问题解决质量和风险指标衡量，而不是文档数量。

## 标签约定

- `[事实]`：可由公开来源、原始资料或实际文件直接核验。
- `[判断]`：基于事实的产品分析，允许被后续证据推翻。
- `[假设]`：尚未充分验证、需要访谈或实验确认的命题。
- `[决策]`：当前阶段选择的方向；若标为“暂定”，须在指定门禁复核。

## 验收门禁

进入阶段 1 前必须由项目负责人确认以下事项：

1. 接受“多渠道消费电子售后”作为首个设计伙伴场景，或给出替代行业。
2. 接受 P0 先做坐席辅助与知识运营闭环，不把全自动客服作为首版目标。
3. 同意北极星指标采用“有效售后问题解决率”，并在阶段 1 建立基线和口径。
4. 确认后续可以获得脱敏客服对话、售后知识、渠道规则和人工处理结果，用于验证假设。
