# 历史版本：初始角色、任务与场景清单（修订前）

版本：V0.1  
状态：阶段 0 草案，待验收  
日期：2026-10-22

## 1. 场景识别原则

场景按“一个具体角色，在什么触发下，需要完成什么判断或动作，失败会带来什么后果”定义。仅描述系统功能、页面或模型能力的内容不计入场景。

优先级是当前产品判断，不是最终开发排期：

- P0：能验证“业务上下文 + 证据 + 风险升级 + 知识闭环”的核心价值；
- P1：在 P0 结果成立后扩展的自动化、消费者端或深度集成；
- 观察：与售后有价值，但容易把项目拉向泛化平台。

## 2. P0 场景

### SC-01 退货条件判断

| 项目 | 内容 |
|---|---|
| 主要角色 | 一线客服、售后专员 |
| 触发 | 客户询问“刚买的耳机能不能退” |
| 关键任务 | 确认购买渠道、签收日期、商品状态和诉求；区分法定无理由、品牌商业政策与质量问题路径 |
| 所需知识 | 消费者权益法规、渠道退货规则、品牌政策、商品完好判定、发票与物流证据 |
| 真实风险 | 把 Apple 在线商店 14 日政策错误套用到所有渠道；忽略远程/线下差异；忽略商品状态与例外 |
| 期望结果 | 给出适用条件、证据清单、可执行入口和不确定项；不能判断时明确升级 |
| 当前证据 | 官方退货页显示 14 个自然日；法律规定远程交易七日无理由；业务资料指出渠道和状态差异 |
| 优先级 | P0 |

### SC-02 质量故障的退换修路径

| 项目 | 内容 |
|---|---|
| 主要角色 | 一线客服、售后专员 |
| 触发 | 客户报告单耳无声、频繁断连、充电异常或续航明显下降 |
| 关键任务 | 先完成基础排查，再按购买时间和故障证据判断退货、换货、维修或检测 |
| 所需知识 | 标准排查顺序、购买/签收时间、保修规则、检测入口和故障证据要求 |
| 真实风险 | 把质量问题错误引导到无理由退货；未排查就承诺换货；遗漏安全信号 |
| 期望结果 | 给出分步骤动作和证据要求，并在达到升级条件时交售后专员 |
| 当前证据 | 官方服务页支持诊断、维修或更换；业务资料整理了不同时间段与权利路径，具体规则需业务复核 |
| 优先级 | P0 |

### SC-03 渠道责任冲突

| 项目 | 内容 |
|---|---|
| 主要角色 | 一线客服、客服主管、渠道运营 |
| 触发 | 订单页、发票、序列号、销售主体与客户描述的渠道不一致 |
| 关键任务 | 识别实际销售/履约主体、可用的售后入口和冲突证据，停止作未经授权的承诺 |
| 所需知识 | 渠道清单、授权经销商/服务商边界、订单与发票规则、冲突升级路径 |
| 真实风险 | 错误承诺品牌方兜底；把授权经销商责任误归品牌自营；客户被在多个入口间反复转交 |
| 期望结果 | 明确“已确认/待核实/冲突”状态，生成给客户的证据清单和内部升级建议 |
| 当前证据 | 官方地点页区分销售与服务地点；业务资料把渠道核验列为判断前置条件 |
| 优先级 | P0 |

### SC-04 安全事件止损与升级

| 项目 | 内容 |
|---|---|
| 主要角色 | 一线客服、售后专员、客服主管 |
| 触发 | 冒烟、异味、鼓包、异常发热、进液、皮肤持续红肿或灼痛 |
| 关键任务 | 立即停止使用/充电，避免危险操作；采集事件信息并转交明确责任方 |
| 所需知识 | 安全 SOP、事件分级、禁止动作、证据要求、紧急联系与升级对象 |
| 真实风险 | 模型继续提供排查步骤；客户拆机、加热、继续充电；延误就医或消防处置 |
| 期望结果 | 回答首先强调风险控制，不生成退换结论；强制进入人工/安全升级流程 |
| 当前证据 | 官方安全资料列出火灾、电击、受伤和损坏风险；业务资料设置了紧急与高风险信号 |
| 优先级 | P0 |

### SC-05 配对与重置排查

| 项目 | 内容 |
|---|---|
| 主要角色 | 一线客服、消费者 |
| 触发 | 只能连接一只耳机、频繁断连或无法与非 Apple 设备配对 |
| 关键任务 | 确认型号、适用设备与当前状态，执行低风险标准步骤；失败后转服务 |
| 所需知识 | 官方操作指南、兼容性边界、重置影响、故障复现条件 |
| 真实风险 | 错误型号步骤；未提示重置会清除配对和个性化设置；反复无效指导 |
| 期望结果 | 给出按状态分支的操作和结果判断，减少重复联系 |
| 当前证据 | 官方支持资料覆盖重启、取消配对、还原和非 Apple 设备连接 |
| 优先级 | P0 |

### SC-06 清洁、防护与使用边界

| 项目 | 内容 |
|---|---|
| 主要角色 | 一线客服、消费者 |
| 触发 | 客户询问清洁方式、能否水洗、运动出汗后使用或降噪影响安全 |
| 关键任务 | 区分可操作步骤、不可做动作、干燥等待和需停止使用的情形 |
| 所需知识 | 官方清洁指南、抗汗抗水说明、安全事项、产品规格 |
| 真实风险 | 以 IP57 推断可游泳；用不当清洁剂；潮湿状态继续充电；忽略听力与医疗设备风险 |
| 期望结果 | 给出明确边界和风险提示；异常持续时转人工或专业渠道 |
| 当前证据 | 官方资料明确防护性能、清洁限制、医疗设备干扰和听力安全要求 |
| 优先级 | P0 |

### SC-07 保修、维修与费用解释

| 项目 | 内容 |
|---|---|
| 主要角色 | 售后专员、消费者 |
| 触发 | 客户要求免费维修、询问保外价格、单只耳机或充电盒丢失 |
| 关键任务 | 区分制造缺陷、正常损耗、人为损坏和丢失；说明检测、预估费用与替代方案 |
| 所需知识 | 保修范围、三包与品牌保修差异、服务价格、检测和授权服务点 |
| 真实风险 | 把正常电池老化承诺为免费保修；把官网估价当成最终报价；遗失问题误导为质量故障 |
| 期望结果 | 提供资格判断所需条件和可核验费用来源，明确“以检测为准”的事项 |
| 当前证据 | 官方服务页列出不同部件保外服务预估价格，并说明检测后确定最终费用 |
| 优先级 | P0 |

### SC-08 规则变更后的知识发布与回归

| 项目 | 内容 |
|---|---|
| 主要角色 | 知识运营、业务审核人、AI 运营 |
| 触发 | 渠道政策、产品资料、安全口径或售后流程发生更新 |
| 关键任务 | 判断影响范围，更新知识，执行高风险与历史问题回归，确认后发布或回滚 |
| 所需知识 | 知识版本、生效时间、适用范围、历史问答、评测集和失败案例 |
| 真实风险 | 新知识覆盖旧知识但未生效；失效政策仍参与回答；旧版本问题重新出现 |
| 期望结果 | 每次变更都能说明影响了什么、验证了什么、谁批准、何时生效 |
| 当前证据 | 官方与业务资料存在明确日期、有效期和渠道差异，说明版本治理是业务必需 |
| 优先级 | P0 |

### SC-09 客服纠错与知识缺口闭环

| 项目 | 内容 |
|---|---|
| 主要角色 | 一线客服、知识运营、客服主管 |
| 触发 | 客服发现答案不可用、来源过期、渠道不匹配或客户问题未被覆盖 |
| 关键任务 | 标记问题类型，保留上下文与证据，分派责任并验证修复 |
| 所需知识 | 原始问答、检索证据、知识版本、错误原因、修复记录和回归结果 |
| 真实风险 | 反馈只停留在群聊；同类问题重复发生；无法判断修复是否有效 |
| 期望结果 | 每个高频或高风险问题都有状态、责任人和可验证的闭环记录 |
| 当前证据 | 这是基于知识运营逻辑的假设，需通过真实客服反馈流程验证 |
| 优先级 | P0 |

## 3. P1 场景

### SC-10 低风险消费者自助

客户通过品牌帮助中心或聊天入口自助解决配对、清洁、状态说明等问题；高风险和安全问题自动转人工。进入 P1 的前提是 P0 已证明低风险场景下的答案忠实度、证据覆盖和转人工可靠性。

### SC-11 售后上下文自动编排

在获得授权和安全控制后，系统从订单、物流、售后工单中获取必要上下文，减少客服手工询问；仍由业务规则决定是否允许自动执行换货预约、维修下单或退款申请。

### SC-12 主管质检与培训

基于真实会话、错误类型和知识版本，生成可解释的质量复盘和培训建议。该场景不应先于 P0 的准确标签与评测集建设。

## 4. 场景优先级依据

### 4.1 先做

`[判断]` 先做 SC-01、SC-02、SC-03、SC-04、SC-07、SC-08、SC-09。它们共同覆盖：

- 高频规则判断；
- 高代价错误；
- 渠道与时间上下文；
- 安全升级；
- 知识发布与问题回归。

SC-05 和 SC-06 是低风险参照场景，用来验证系统在普通操作指导中是否同样可用，但不应让产品退化为操作手册搜索。

### 4.2 延后

`[判断]` 消费者端自动回答、订单自动执行、质检培训和跨渠道主动通知放在 P1。原因是它们会同时放大错误、增加集成和数据合规成本，且无法替代“建议是否有效”的核心验证。

## 5. 场景验收问题

阶段 1 对每个 P0 场景必须收集：

1. 真实用户原话的至少一类变体；
2. 当前人工处理步骤和耗时来源；
3. 判断所需的全部上下文；
4. 不可接受错误的定义；
5. 业务结果的记录方式；
6. 升级或停止处理的明确条件；
7. 可追溯知识的责任人与更新机制。

没有真实证据的场景，不应进入阶段 2 的信息架构与状态机设计。
