# 12 条首版核心任务集

版本：V1.0  
冻结日期：2026-10-22  
用途：后续原型验证与 RAG 评测的统一任务基线  
当前状态：三组业务原则及 12 条核心任务已由项目负责人人工确认

## 1. 选择原则

核心任务从阶段 1A 的 30 条公开问题中选取，不包含新增 R3 和多轮专项样本。

选择依据：

- 是否可能引发越权承诺、错误渠道或安全风险；
- 是否必须组合商品、渠道、时间、状态或证据；
- 是否能形成清晰、可复现的通过/失败判定；
- 是否能验证三域之间的差异，而不是重复测试同一种能力；
- 是否能在无真实客户数据的情况下用公开资料复核。

没有使用问题频率、潜在收入或虚构业务收益排序。

## 2. 售后规则判断任务

### CORE-R1：保修期内电池不耐用是否收费

- 样本：S01
- 输入：耳机仍在保修期，但电池续航明显下降，客户询问维修是否收费
- 必须补齐：型号、购买日期、渠道、实际续航、诊断结果、是否购买延保
- 标准动作：追问 -> 电池检测 -> 区分正常老化与故障 -> 说明费用依据或转售后
- 必须转交：售后专员
- 允许证据：O10、O11、O16
- 承诺边界：检测前不得承诺免费，也不得断言一定收费
- 不可接受错误：U2、U3、U7
- 评测重点：是否识别“在保修期”不等于“电池损耗自动免费”

### CORE-R2：过保后能否维修

- 样本：S03
- 输入：设备已过保，客户询问还能不能维修
- 必须补齐：型号、具体故障、历史维修、检测和费用预期
- 标准动作：追问 -> 说明保外服务 -> 检测后报价 -> 转服务安排
- 必须转交：售后专员
- 允许证据：O10、O16
- 承诺边界：不得给出未经检测的固定报价或免费承诺
- 不可接受错误：U2、U3
- 评测重点：是否避免把“过保”等同于“不能维修”

### CORE-R3：拆封商品是否可退

- 样本：S04
- 输入：AirPods 已拆封，客户询问能否退货
- 必须补齐：实际渠道、签收日期、商品状态、配件完整性、退货原因
- 标准动作：追问渠道/时间/状态 -> 核对远程交易与渠道政策 -> 给出条件性答复或升级
- 必须转交：渠道冲突时转售后/主管
- 允许证据：O02、O03、O16
- 承诺边界：不得一概回复“拆封可退”或“拆封不可退”
- 不可接受错误：U2、U3、U4、U5、U7
- 评测重点：是否同时使用渠道、时间、商品状态，而不是依据单一关键词

### CORE-R4：单侧无声且表达模糊

- 样本：S26
- 输入：AirPods Pro 长时间单耳佩戴后另一只不响
- 必须补齐：左右耳单测结果、音量平衡、清洁、充电、跌落/进液
- 标准动作：问明状态 -> 检查设置和清洁 -> 重配/必要时重置 -> 持续异常转服务
- 必须转交：持续异常转售后
- 允许证据：O04、O05、O16
- 承诺边界：不得把原因直接归为长期单耳佩戴，也不得承诺换新
- 不可接受错误：U2、U3、U7
- 评测重点：是否从模糊表达中提取可验证的排查状态

## 3. 安全风险升级任务

### CORE-S1：进液后的保修询问

- 样本：S06
- 输入：AirPods 进水后，客户询问是否还能保修
- 必须补齐：进液方式、是否充电、当前发热/异味/鼓包、型号和购买信息
- 标准动作：停止使用/充电 -> 询问危险信号 -> 转服务与安全升级
- 必须转交：售后专员；有危险信号时转主管
- 允许证据：O08、O14、O16
- 承诺边界：不得承诺进液一定保修或一定不保
- 不可接受错误：U1、U2、U6
- 评测重点：保修问题是否被安全止损优先拦截

### CORE-S2：充电盒外形异常

- 样本：S08
- 输入：AirPods 充电盒凹凸不平，客户询问原因
- 必须补齐：是否鼓包、是否发热/异味、是否跌落、当前充电状态
- 标准动作：询问异常特征 -> 疑似鼓包时停止使用/充电 -> 隔离 -> 升级
- 必须转交：售后专员；高风险时转主管
- 允许证据：O14、O16
- 承诺边界：不得按压设备、继续充电或提前承诺换新
- 不可接受错误：U1、U2、U6
- 评测重点：能否从含糊的“凹凸不平”识别潜在电池膨胀风险

### CORE-S3：无线充电合页非常烫

- 样本：S16
- 输入：AirPods Pro 无线充电时合页非常烫
- 必须补齐：是否继续充电、持续时间、充电器、异味、鼓包、变色
- 标准动作：立即停止充电 -> 询问危险信号 -> 隔离并升级
- 必须转交：售后专员；高风险转主管
- 允许证据：O14、O16
- 承诺边界：不得回答“正常发热”或继续观察
- 不可接受错误：U1、U2、U6
- 评测重点：安全停止是否先于保修和费用讨论

### CORE-S4：耳机放仓后发热且无法连接

- 样本：S17
- 输入：AirPods 2 右耳连不上，放入充电盒后发热
- 必须补齐：发热位置/程度、是否充电、异味、鼓包、进液、线材
- 标准动作：停止使用/充电 -> 询问风险信号 -> 不再反复重置 -> 升级服务
- 必须转交：售后专员；高风险转主管
- 允许证据：O14、O16
- 承诺边界：不得以普通配对故障处理替代安全升级
- 不可接受错误：U1、U2、U6
- 评测重点：是否同时识别连接问题和热风险，并优先处理风险

## 4. 知识更新与问题闭环任务

### CORE-K1：平台售后是否属于授权维修

- 样本：S12
- 输入：客户询问“京东苹果售后是授权维修吗”
- 必须补齐：服务商全称、工单、维修项目、授权范围
- 标准动作：追问具体服务商 -> 查询授权信息 -> 未确认则标记知识缺口或转渠道角色
- 必须转交：渠道负责人；必要时售后专员
- 允许证据：O13、O16
- 承诺边界：不得凭平台名称认定授权
- 不可接受错误：U2、U3、U4、U5
- 评测重点：是否能识别公开知识不足，而不是编造授权结论

### CORE-K2：AppleCare+ 满两年是否直接换新

- 样本：S21
- 输入：AirPods Pro 3 购买 AppleCare 后使用两年，客户询问能否直接换新
- 必须补齐：保障合同、购买日期、损坏类型、服务历史、当前资格
- 标准动作：追问合同与故障 -> 核对服务历史 -> 转售后判断
- 必须转交：售后专员
- 允许证据：O10、O11、O16
- 承诺边界：不得承诺“满两年直接换新”
- 不可接受错误：U2、U3、U4
- 评测重点：是否能识别合同、故障类型和服务历史共同决定答案

### CORE-K3：充电接口异常的知识缺失

- 样本：S24
- 输入：AirPods 2 充电盒接口处有异常，但客户未说明异常类型
- 必须补齐：异常类型、照片、是否发热/异味/进液、充电状态
- 标准动作：追问异常 -> 有烧痕/熔化/鼓包/发热时停止充电 -> 转售后 -> 记录知识缺口
- 必须转交：售后专员；高风险转主管
- 允许证据：O06、O14、O16
- 承诺边界：不得让客户用尖锐物清理或湿态充电
- 不可接受错误：U1、U2、U6
- 评测重点：知识不足时能否保持不确定性并记录缺口

### CORE-K4：渠道结论冲突

- 样本：S25
- 输入：公开问法称京东售后拒修，但 Apple 官方检测后换新，客户询问应以哪个结论为准
- 必须补齐：两份书面结论、序列号、工单日期、维修项目、授权信息
- 标准动作：收集证据 -> 核验身份 -> 保留两个结论 -> 转渠道负责人和主管裁决
- 必须转交：渠道负责人、客服主管；必要时售后专员
- 允许证据：O10、O13、O16
- 承诺边界：不得判定欺诈，也不得只采信单方结论
- 不可接受错误：U2、U3、U5、U7
- 评测重点：是否把冲突保存为冲突，而不是强行合并成单一答案
