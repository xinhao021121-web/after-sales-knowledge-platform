# 首版需求优先级收口

版本：V1.0  
日期：2026-10-22  
边界：首版需求验证，不是最终版本路线图

## 1. 排序方法

本次不使用虚构的问题频率、利润或客户收益。优先级只依据：

| 维度 | 判定问题 |
|---|---|
| 风险后果 | 错误会不会造成安全、权益、渠道责任或信任损失 |
| 证据完整度 | 是否有公开、可追溯、可复核的处理依据 |
| 可测试性 | 能否用当前 36 条样本形成明确通过/失败 |
| 学习价值 | 能否排除三类验证域中的核心不确定性 |

不使用数值加权，因为当前没有真实的错误代价、频率和业务收益数据来支撑权重。

## 2. 首版必须验证

| 需求 | 风险后果 | 证据完整度 | 可测试性 | 学习价值 | 首版判断 |
|---|---|---|---|---|---|
| N1 业务上下文识别与追问 | 高：缺条件会产生错误规则 | 中：模拟规则可定义，真实流程未验证 | 高：M01-M03 和 30 条样本可测 | 高：决定规则判断是否成立 | 必须验证 |
| N2 安全停止与升级 | 高：漏升级可能造成伤害 | 高：官方安全资料支持 | 高：S06-S09、S16-S20、S31-S33 可测 | 高：决定产品是否可进入售后场景 | 必须验证 |
| N3 渠道/销售主体核验 | 高：易产生错误兜底和客户推诿 | 中：渠道公开展示，实际组织未验证 | 高：S11-S15、S25 可测 | 高：决定企业客户是否需要专门平台 | 必须验证 |
| N4 规则条件的组合判断 | 高：单条件答案容易误导 | 中高：公开规则可引用 | 高：S01-S05、S21-S24 可测 | 高：区分普通问答与售后决策 | 必须验证 |
| N5 有效证据和版本约束 | 高：过期/不适用来源会放大错误 | 高：可统一来源格式 | 高：每条任务可标证据 | 高：决定答案是否能审计 | 必须验证 |
| N6 确定性与冲突处理 | 高：把冲突写成确定结论会误导 | 中：需模拟规则裁决 | 高：S25 和不确定样本可测 | 高：决定系统可否安全上线 | 必须验证 |

## 3. 延后验证

| 需求 | 延后原因 | 需要的前置条件 |
|---|---|---|
| N9 消费者端低风险自助 | 会放大错误并提供额外入口 | P0 的规则、安全和证据能力先通过评测 |
| N10 订单/物流/CRM 深度集成 | 涉及系统边界和数据授权 | 先确认上下文字段和任务需求 |
| N11 自动执行退换、预约或补偿 | 风险高且需要明确权限 | 先验证人工确认流程和业务审批 |
| N12 多品牌、多语言和经销商门户 | 会分散首版验证 | 三域基线稳定后再扩展 |
| N13 运营分析、质检和培训建议 | 依赖稳定标签和真实过程数据 | 先完成人工标注和模拟回归 |
| N14 面向消费者的主动通知 | 需要真实事件来源和授权 | 订单系统和通知策略明确后验证 |

## 4. 暂不设计

| 内容 | 原因 |
|---|---|
| 信息架构和页面结构 | 本阶段只做需求验证 |
| PRD、状态机和权限矩阵 | 需在核心任务人工确认后另行设计 |
| 模型、向量库、Top K、切片和重排参数 | 当前没有同条件评测结果，不能先定技术参数 |
| 退款、赔偿、保修审批自动化 | 涉及越权承诺和真实责任 |
| 医疗诊断、法律结论 | 超出产品责任和专业能力边界 |
| 替代 CRM、订单、物流和售后工单系统 | 不是当前要验证的判断能力 |
| 泛企业内部搜索、营销生成、销售话术 | 与首版三域边界不一致 |
| 多租户计费、插件市场、渠道分润 | 尚未验证首个业务价值 |

## 5. 需求的验证顺序

建议按风险与依赖顺序执行：

1. N2 安全停止与升级；
2. N1 业务上下文识别与追问；
3. N3 渠道/销售主体核验；
4. N4 规则条件组合；
5. N5 有效证据和版本；
6. N6 冲突与不确定性；
7. N7 知识缺口闭环；
8. N8 标准任务集回归。

`[说明]` 顺序不是开发排期，也不是技术优先级，只表示后续模拟评测中先验证哪些业务风险。

## 6. 首版不承诺的结果

本项目当前不能声称：

- 能减少多少客服工时；
- 能提升多少解决率；
- 能降低多少投诉或赔付；
- 能覆盖真实客户的多少问题；
- 能自动替代多少人工；
- 能产生任何真实商业收益。

这些结果需要真实业务环境和授权数据，超出模拟案例的证据能力。
