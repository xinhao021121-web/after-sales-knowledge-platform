# 产品推荐与未采用方案

## 明确推荐

**继续使用 `deepseek-v4-pro` 作为默认模型；不启用 Flash 自动路由。
Flash 只允许作为内部、离线、低风险的实验候选。**

理由：

1. 三组硬门禁均未退化，但样本只有一轮，且 Flash 在 B/C 两轮的初轮通过率不同；
2. Flash 直接模式在本次固定集上没有新增语义失败，Token 和延迟明显更低，值得继续研究；
3. C 回退率为 26.3%，只恢复 2/5 路由门禁，最终语义仍与 B 相同；
4. C 比 B 多约 11.7% Token、5.3% 平均延迟，官方列表价估算高约 78%；
5. C 的路由门禁仍未发现人工抽样中的弱下一步，不能据此自动上线；
6. `RET-H09` 在全部组失败，证明模型路由不能解决已有检索/分类缺陷。

## 未采用

### 全量 Flash 替代 Pro

本次数据不支持“Flash 明显更差”，但也不足以支持替换：任务状态有漂移，
B/C 两轮 Flash 存在波动，人工样本出现动作质量差异。保持 Pro 默认更稳妥。

### Flash 优先 + 自动 Pro 回退

未采用。相对直接 Flash 没有语义收益，却增加调用、延迟、Token 和运维复杂度；
人工抽样还发现自动门禁漏判了较弱建议动作。

### 继续增加新题目

未采用。固定 27 条是唯一实验口径，后续应在同一集合重复验证，通过后才另建最终测试集。
