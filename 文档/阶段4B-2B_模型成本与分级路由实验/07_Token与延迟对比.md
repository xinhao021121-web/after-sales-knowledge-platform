# Token 与延迟对比

| 指标 | A Pro | B Flash | C 混合 |
|---|---:|---:|---:|
| 模型调用 | 19 | 19 | 24 |
| 输入 Token | 28,169 | 27,162 | 34,115 |
| 输出 Token | 52,650 | 33,791 | 33,945 |
| 总 Token | 80,819 | 60,953 | 68,060 |
| 每个有效回答 Token | 10,102 | 6,095 | 6,806 |
| 每个正确来源命中 Token | 5,773 | 4,354 | 4,861 |
| 平均延迟 | 38,004 ms | 14,421 ms | 15,190 ms |
| P95 延迟 | 79,939 ms | 27,440 ms | 38,511 ms |

相对 A：

- B 总 Token 减少约 24.6%，平均延迟减少约 62.1%；
- C 总 Token 减少约 15.8%，平均延迟减少约 60.0%。

相对 B：

- C 总 Token 增加约 11.7%；
- C 平均延迟增加约 5.3%，P95 增加约 40.4%；
- C 的 5 次回退没有带来相对 B 的新增语义通过。

因此 C 相比 Pro 更轻，但相比直接 Flash 没有质量收益，且成本更高。该差异是
内部实验观察，不构成生产性能承诺。
