# 无障碍与窄屏最低要求

日期：2026-10-23
基线：WCAG 2.2 AA 的结构与交互原则

## 1. 无障碍最低要求

- 所有页面有唯一 `h1` 和连续标题层级；
- 主导航、主工作区、上下文区使用可识别地标；
- 所有按钮、输入、筛选器和状态标签有可读名称；
- 键盘可完成创建、筛选、打开详情、确认和返回；
- 焦点始终可见，焦点顺序与视觉阅读顺序一致；
- 状态不能只用颜色表达，必须同时有文字和图标/形状语义；
- 错误与成功信息使用可读提示，并报告给辅助技术；
- 打开抽屉、弹窗或行内确认后，焦点进入新区域；关闭后回到触发点；
- 破坏性操作不能仅靠键盘自动确认；
- 表格必须有列标题；卡片列表保留等价字段名称；
- 图标按钮必须提供文字替代或可访问名称；
- 状态变更、风险止损、审批拒绝和发布结果使用礼貌或高优先级提示，但不连续打断。

## 2. 窄屏最低要求

- 在 320 CSS px 宽度下，页面核心内容可纵向阅读，不要求双向滚动；
- 复杂权限矩阵和大数据表允许局部横向滚动，但关键对象 ID、状态和下一步必须先可见；
- 左侧导航折叠为角色导航面板，当前工作面和活动角色始终可见；
- P03 在窄屏下按“风险提示 → 缺失字段 → 证据 → 建议 → 操作”排序；
- P05 在窄屏下先显示停止危险动作，再显示风险证据和升级；
- P09 将 CASE_LINK 列表转为轨道卡片，每卡显示 knowledge_item、LINK 状态和下一步；
- P11 将发布影响和回滚历史按顺序堆叠，不能把重要审批按钮固定在屏幕外；
- P13 时间线和长文本可换行，不截断状态、责任人和事件名称；
- 触控目标至少遵循 WCAG 2.2 AA 的最小目标要求，并为关键动作预留更大点击区域；
- 横屏、分屏和 200% 文本缩放不丢失主操作或状态提示；
- 打印或导出不依赖悬停、动画和颜色。

## 3. 内容可读性

- 状态同时显示用户语言和必要代码，如“待补上下文（ASQ_CONTEXT_PENDING）”；
- 错误说明采用“发生了什么、保留了什么、下一步做什么”；
- 风险等级使用文字 `R2`/`R3` 与处置说明，不只使用红色；
- 数量关系明确写“0 条/1 条/N 条 LINK”，避免“有关联”之类模糊表达；
- 时间显示时区，数量与计数单位不省略。

## 4. 验收方式

- 键盘走通 13 条关键流程的主路径和至少一个失败路径；
- 320px 窄屏检查 13 个页面无关键内容截断；
- 屏幕阅读器抽查 P03、P05、P09、P11、P12；
- 禁用颜色后仍可区分状态、风险和主要操作；
- 200% 文本缩放后仍能看到当前状态和下一步。
