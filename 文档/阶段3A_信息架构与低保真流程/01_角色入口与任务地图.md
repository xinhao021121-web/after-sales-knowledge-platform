# 角色入口、默认首页与任务地图

日期：2026-10-23

## 1. 通用进入方式

`[模拟企业规则]` 所有角色通过企业 SSO 登录。系统按实际角色签发会话，不提供匿名入口。多角色用户必须切换到明确的活动角色；切换后重新计算页面权限、数据范围和职责分离。

页面 ID 对应《页面清单》。

P01 是同一个“今日工作台”页面的角色化视图，不是重复首页；用户通过活动角色和深链进入对应视图。

|---|---|---|---|---|

## 3. 导航差异

系统不向所有角色展示完全相同的导航。

| 角色 | 不展示或只读的能力 | 导航差异原因 |
|---|---|---|
| 一线客服 | 不显示来源编辑、知识审批、评测配置、发布操作 | 避免把知识治理和维护责任混入一线答复 |
| 售后专员 | 不显示业务政策批准、REL 发布 | 售后判断不等于业务批准 |
| 客服主管 | 不显示来源原文编辑；CTX 只读；不代替 R3 法务确认 | 可建单、转交并确认/发送 ADV，但不能编辑 CTX，保持判断与上下文留痕分离 |
| 业务/渠道负责人 | 不显示逐条样本调试、系统权限配置 | 只处理政策口径、渠道范围与批准 |
| 知识运营 | 不显示业务批准按钮、R3 专业结论按钮、系统权限配置 | 可执行但不可代替他人批准 |
| AI 评测人员 | 不显示 KB 发布批准、业务口径修改、R3 关闭 | 评测证据不等于政策或安全批准 |
| 法务/安全责任人 | 不显示知识普通编辑、系统权限配置 | 聚焦高风险判断和证据审查 |
| 系统管理员 | 默认不展示客户业务内容；无业务审批和发布按钮 | 只负责身份、权限和技术运行 |

## 4. 角色任务地图

| 角色 | 进入后先看什么 | 主路径 | 失败或冲突时 | 完成/离开 |
|---|---|---|---|---|
| 一线客服 | 我的待处理咨询、未补字段、待确认建议 | P01 → P02/P03 → 确认或转交 | 追问、风险升级、冲突转交 | ASQ_RESPONDED/RESOLVED/CLOSED |
| 售后专员 | 待售后、检测待补、渠道冲突 | P02 → P03 → P05（如风险） | 补证、转主管/渠道、创建 CASE | ASQ_RESOLVED 或 HANDOFF_PENDING |
| 客服主管 | 待分派 ASQ、R2/R3、SLA 风险、待发布、待复核 CASE | P01 → P02/P03/P04/P05/P08/P09/P11 | 创建/转交、确认或发送符合权限的 ADV；退回、升级安全、拒绝发布、要求回归 | ASQ 回复/转交完成、风险关闭、发布决策、CASE 闭环 |
| 业务/渠道负责人 | 待审口径、待批发布、待批弃置/无修复关闭 | P01 → P07 或 P11/P09 | 拒绝、退回修改、要求渠道证据 | 业务决定完成并有审计 |
| 知识运营 | 来源到期、KB 失败、CASE 修复、待发布 | P01 → P06/P07/P09/P10/P11 | 新建版本、后继 LINK、回滚、弃置 | KB/LINK/REL/ CASE 进入下一合法状态 |
| AI 评测人员 | 待执行 EVAL、失败分类、回归证据 | P01 → P10 → P09/P11 | 阻塞、失败、重跑、提供证据 | EVAL_PASSED/FAILED/BLOCKED |
| 法务/安全责任人 | R3 待处置、危险内容、来源安全变化 | P04 → P05 → P08/P09（如需） | 强制止损、升级、要求补充证据 | ESC_CLOSED 或继续监控 |
| 系统管理员 | 权限异常、审计缺失、系统降级 | P12 → P13 | 阻断动作、恢复配置、通知责任角色 | 权限/审计/集成状态恢复或保持显式故障 |

## 5. 多角色与授权原则

- 页面导航按活动角色显示，权限由服务端再次校验；
- 多角色切换不合并审批权，个人仍不能批准自己提交的内容；
- 无权限页面可从深链看到最小“无权限”反馈，不泄露业务内容；
- 页面隐藏按钮不能替代系统拦截；
- 任何关键角色缺失时，系统保持待处理并显示责任空位，不以普通角色代签。
