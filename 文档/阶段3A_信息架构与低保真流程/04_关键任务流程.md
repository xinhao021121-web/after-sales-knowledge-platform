# 关键任务低保真流程

日期：2026-10-23
对应流程图：[03_关键任务流程.drawio](diagrams/03_关键任务流程.drawio)

## F01 一线客服创建咨询任务并补齐上下文

- **起点**：客户提出售后问题或客服工作台打开“售后助手”。
- **主路径**：P01 → P02 创建 ASQ → P03 录入原始诉求 → 系统生成缺失字段清单 → 客户补充 → 新 CTX 版本 → 可进入判断。
- **判断分支**：若诉求可识别且上下文达到最低条件，进入 F03；若关键字段缺失，停留在 P03 的“待补上下文”区；若发现危险信号，转入 F04。
- **失败路径**：重复请求、无权限、保存冲突或上下文来源不可用。
- **恢复动作**：返回原 ASQ、使用幂等键复用原任务、刷新版本后重试、改为人工记录待补证。
- **终点**：ASQ_ASSESSING，或转风险流程。
- **页面**：P02、P03、P04。

## F02 证据不足时追问和补证

- **起点**：P03 已具备部分 CTX，但证据缺失、过期或与诉求不匹配。
- **主路径**：展示缺失字段/证据原因 → 客户或售后补充材料 → 新 CTX 版本 → 重新检索 EVD → 生成条件性建议。
- **判断分支**：证据有效则进入 F03；冲突则保留双方证据并转交；始终无证据则创建 CASE。
- **失败路径**：客户拒绝提供、外部系统不可用、来源失效或证据无法核验。
- **恢复动作**：保持待补证/转人工/创建 CASE，不生成确定结论。
- **终点**：ASQ_ASSESSING、ASQ_CONTEXT_PENDING 或 CASE_OPEN。
- **页面**：P03、P06、P09。

## F03 条件性建议、承诺拦截和人工确认

- **起点**：P03 已有有效 EVD 或明确知识缺口。
- **主路径**：生成 ADV → 展示满足/未满足条件、承诺边界、禁止动作 → 人工核对 → 发送或驳回。
- **判断分支**：有越权承诺则 BLOCK/REQUIRE_APPROVAL；风险出现转 F04；无依据则回 F02。
- **失败路径**：确认人无权限、ADV 版本过期、风险复检失败、发送接口失败。
- **恢复动作**：重新生成 ADV、补证、转售后/主管/业务，不存在绕过确认的发送按钮。
- **终点**：ASQ_RESPONDED；未解决则继续 ASQ_ASSESSING/HANDOFF_PENDING。
- **核心任务**：CORE-R1、CORE-R2、CORE-R3、CORE-R4。
- **页面**：P03、P04、P05。

## F04 R2/R3 安全止损和升级

- **起点**：P03 识别冒烟、鼓包、进液后异常、持续发热、异味、伤害等风险信号。
- **主路径**：暂停普通建议 → 创建 ESC_CANDIDATE → 立即发送停止使用/充电、隔离、禁止拆机等止损动作 → 确认风险 → 按 R2/R3 转主管或安全/法务。
- **判断分支**：风险排除 → EV-02 恢复 ASQ；风险关闭 → EV-03 恢复 ASQ；仍危险 → ESC_MITIGATING/ESCALATED。
- **失败路径**：客户拒绝止损、无接收人、审计失败、R3 权限缺失。
- **恢复动作**：持续显示止损、保持升级待办、通知责任角色；不得回到普通售后建议。
- **终点**：ESC_CLOSED 或 ESC_DISMISSED，ASQ 回到重新评估。
- **页面**：P04、P05、P03。

## F05 来源失效触发 KB/EVAL/REL/LINK 阻断

- **起点**：P06 来源到期、撤回、不可访问或被官方替代。
- **主路径**：来源状态变化 → 展示影响清单 → 阻断新引用/新评测/新发布 → KB_SOURCE_BLOCKED、EVAL_BLOCKED、REL_REJECTED/SUSPENDED → EV-18 更新 LINK/CASE。
- **判断分支**：受影响的 CASE 未关闭 → CASE_FIXING；已关闭 → CASE_REOPENED；无 CASE → 创建 CASE_OPEN 与 LINK_OPEN。
- **失败路径**：影响分析超时、部分对象更新失败、外部追溯不可用。
- **恢复动作**：先阻断对外引用和新发布，保留审计和治理待办；重试仅补齐对象，不回滚已生效的安全阻断。
- **终点**：受控阻断完成，或进入 CASE 修复。
- **页面**：P06、P09、P10、P11。

## F06 CASE 创建、分诊和修复

- **起点**：P03/P05/P10 出现错误、缺口、冲突、评测失败或发布异常。
- **主路径**：创建 CASE → P08 列队 → P09 分诊 → CASE_EVIDENCE_READY → CASE_FIXING → EV-14 创建 KB_DRAFT 和 LINK_OPEN → EV-10 创建 EVAL。
- **判断分支**：需要知识修复则进入 LINK 流程；无需知识修复则进入 F12 双角色批准；证据不足则 CASE_DEFERRED。
- **失败路径**：责任人缺失、重复 CASE/LINK、来源或审计不可用。
- **恢复动作**：复用原 CASE/LINK、补充责任人、恢复依赖后再提交；不得用聊天备注替代 CASE。
- **终点**：CASE_REGRESSION_PENDING 或受控延期/关闭。
- **核心任务**：CORE-K1、CORE-K3、CORE-K4。
- **页面**：P08、P09、P07。

## F07 CASE 关联 0/1/N 个 KB_LINK

- **起点**：P09 打开一个 CASE 的修复计划。
- **主路径**：展示 LINK 列表 → 将不同 knowledge_item 分组成独立修复轨道 → 每个知识条目最多一条活动 LINK → 点击进入 KB、EVAL、REL。
- **判断分支**：0 条 LINK 显示“无需知识修复”受控入口；1 条显示单链路；N 条显示部分完成计数和各知识条目状态。
- **失败路径**：同知识条目重复开链、previous_link_id 非法、旧 LINK 被尝试改写。
- **恢复动作**：拒绝新链或引用、展示失败审计、返回原历史链；使用已有活动链。
- **终点**：P09 显示统一 CASE 聚合状态和全部轨道下一步。
- **页面**：P09、P07、P10。

## F08 部分 KB 完成、全部 KB 完成和明确弃置

- **起点**：CASE 有多个知识条目的 LINK，其中部分已发布或失败。
- **主路径**：每个 LINK 显示当前状态和下一步 → 部分完成时 CASE 保持 FIXING/PENDING_RELEASE → 全部最新 LINK 为 RELEASED/ABANDONED 后 CASE 可关闭。
- **判断分支**：仍有 OPEN/PENDING → 不得关闭；最新 LINK FAILED → CASE_FIXING；业务批准弃置 → EV-19 → LINK_ABANDONED。
- **失败路径**：业务批准缺失、审计失败、其他知识条目仍未完成。
- **恢复动作**：保持 CASE 打开，显示“为什么不能关闭”和未完成 LINK；继续修复或申请明确弃置。
- **终点**：全部轨道终止后 CASE_CLOSED，否则保持可继续状态。
- **页面**：P09、P11。

## F09 EVAL 通过、REL 拒绝和重试

- **起点**：P10 执行 EVAL，候选 KB 与样本版本冻结。
- **主路径**：EVAL_RUNNING → PASSED → EV-08 更新 LINK_PENDING_RELEASE、CASE 聚合、创建 REL_PENDING_APPROVAL → P11 审批。
- **判断分支**：主管批准 → EV-16 激活；主管拒绝 → EV-20 将 LINK_FAILED、CASE_FIXING；评测失败 → EV-09 回到修复。
- **失败路径**：评测服务中断、匹配 LINK 数异常、REL/LINK/审计写入失败。
- **恢复动作**：EVAL_BLOCKED 或保留待审批；拒绝后 P09 显示新修复入口；重试使用幂等键。
- **终点**：REL_ACTIVE 或受控回到 CASE_FIXING。
- **页面**：P10、P11、P09、P07。

## F10 发布生效、LINK 释放和 CASE 聚合关闭

- **起点**：P11 打开 REL_PENDING_APPROVAL，审批与来源均有效。
- **主路径**：EV-16 激活新 REL → EV-11 将匹配 LINK 更新为 RELEASED → 按全部知识条目最新 LINK 聚合 CASE -> 满足门禁则 CASE_CLOSED。
- **判断分支**：其他 LINK 仍活动或失败 → CASE 保持 FIXING/PENDING_RELEASE；一个知识条目已有 ACTIVE → 旧 REL 被替代。
- **失败路径**：审计失败、ACTIVE 唯一性冲突、聚合计算失败。
- **恢复动作**：保持原 REL/LINK/CASE 状态并重试；不显示“已关闭”直到所有目标更新成功。
- **终点**：REL_ACTIVE 且 CASE 可安全关闭或继续等待。
- **页面**：P11、P09、P13。

## F11 REL 停用、回滚和后继 LINK

- **起点**：已生效 REL 出现错误、来源失效或业务要求回退。
- **主路径**：停用当前 REL → 选择历史目标并创建新 REL_PENDING_APPROVAL → 重新核验来源/业务/评测 → 激活新候选 → 历史 LINK 保持 RELEASED，创建后继 LINK_OPEN，CASE 重开或修复。
- **判断分支**：目标来源失效或审批缺失 → 保持 SUSPENDED/REJECTED；重复请求 → 返回原候选；已有活动 LINK → 不重复开链。
- **失败路径**：回滚候选创建失败、审计失败、后继 LINK 失败。
- **恢复动作**：保持停用状态和治理待办；人工安全处置；重试同 request ID。
- **终点**：新 REL_ACTIVE 且受影响 CASE/LINK 可见下一步，或显式保持停用。
- **页面**：P11、P09、P06、P13。

## F12 无 LINK CASE 的“无需知识修复”审批

- **起点**：P09 分诊确认该 CASE 不涉及知识修改，只需要流程/培训/单次处置。
- **主路径**：填写根因、责任人、无需修复理由 → 主管审批 → 业务/渠道负责人独立审批 → 生成审计 → CASE_CLOSED。
- **判断分支**：缺少任一批准 → 保持 CASE_FIXING；重复提交 → 返回原关闭结果；存在活动 LINK → 阻止使用该路径。
- **失败路径**：审批人冲突、理由不足、审计写入失败。
- **恢复动作**：补齐独立批准或改为知识修复；显示关闭门禁原因。
- **终点**：CASE_CLOSED（0 LINK），或转 F06/F07。
- **页面**：P09、P12、P13。

## F13 ESC 关闭后风险复发创建新 ESC

- **起点**：同一客户已有关闭或已排除 ESC；新消息再次出现风险。
- **主路径**：P03/P05 识别新风险 → 创建新 ESC_CANDIDATE → 关联同客户终态旧 ESC → 暂停当前 ASQ → 立即止损。
- **判断分支**：previous_esc_id 合法且单后继 → 保存；自引用/非终态/循环/重复后继 → 拒绝并写失败审计。
- **失败路径**：旧 ESC 历史异常、客户/任务不匹配、审计失败。
- **恢复动作**：先进入安全处置，不依赖历史关联成功；修复引用后重试；旧 ESC 保持只读。
- **终点**：新 ESC 进入 CONFIRMED/MITIGATING，旧 ESC 终态不变。
- **页面**：P05、P03、P04、P13。

## 流程完备性规则

- 每个流程都由明确用户动作或系统事件启动；
- 每个判断至少包含正常、失败/例外和恢复分支；
- 每个终点都有对象状态或明确保持态；
- 失败分支不得只停留在 toast，必须保留可继续对象；
- 流程图中的页面跳转与页面清单一致。
