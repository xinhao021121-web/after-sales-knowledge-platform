# 接口契约更新

OpenAPI 文件：[contracts/bff-p03.openapi.json](contracts/bff-p03.openapi.json)。

## GET /api/health

返回 BFF、Adapter、Dify Advanced Chat、当前环境、模型和 P0 门禁状态。测试环境真实返回 `status=ok`。

## POST /api/retrieval/search

输入字段与 `/api/answers` 一致，返回真实检索元数据：

- `request_id`；
- `status`；
- `hits`；
- 每条引用的 `doc_id`、`segment_id`、`kb_id`、`kb_version_id`、来源状态；
- `supported_claims` 与 `traceable`；标题型切片不计为可追溯引用；
- 过期/权限/未映射过滤计数；
- `provider_request_id` 与 `timing_ms`。

## POST /api/answers

返回：

- `answer_status`；
- `answer`、`suggested_action`；
- `business_conditions`；
- `citations`；
- `citation_support`；
- `risk`；
- `provider_request_id`、`request_id`、`timing_ms`、`error_code`；
- `provider_called`、`source_mode` 与幂等重放标识。
- `cost`：provider、model、输入/输出/总 token、供应商延迟、估算成本、`COST_UNKNOWN`、回答状态、claim 门禁和有效回答标记。

浏览器不会接收到 Dify Base URL、Bearer Token、API Key 或原始供应商响应。

只有全部回答引用均能映射到含具体 `supported_claims` 的切片时，`citation_support.passed` 才为 `true`。否则 `ANSWERED` 强制降级为 `NEED_CLARIFICATION`。

每条输出引用单独校验；标题型引用被丢弃，正文切片只有与回答主张达到保守字面覆盖时才可由 BFF 补映射。
