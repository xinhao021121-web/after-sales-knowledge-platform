# 数据持久化与凭据

## 1. 本地数据

- `阶段3B_高保真交互原型/data/catalog.json`：从阶段 4A 公开资料清单生成的来源目录；
- `data/runtime/idempotency.json`：幂等键、请求指纹与归一化响应；
- `data/runtime/audit.ndjson`：脱敏审计记录。
- `data/runtime/stage4b1-e2e/`：普通 E2E 的原始响应与截图。

`data/runtime/` 由 `.gitignore` 排除。审计只写角色、对象、结果、状态、耗时、错误码、问题哈希和长度，不写问题原文或供应商密钥。

真实 E2E 默认只写入 `data/runtime/`。只有显式执行
`node tests/e2e-bff.mjs --update-examples` 才会更新
`examples/` 下的固定样例和交付截图，避免常规验证污染 Git 工作区。

## 2. 浏览器持久化

P03 使用原 `localStorage` 状态键保存：

- 角色与当前页面；
- 真实 RAG 开关；
- 输入问题与商品/渠道；
- 归一化结果与引用；
- 用户确认状态；
- 幂等请求键。

API Key 不进入 localStorage、DOM、页面源码或网络响应。

## 3. 自由文本隐私门禁

手机号、邮箱、验证码、密码、支付凭证、完整序列号、身份证和详细地址在 BFF 调用 Dify 前被阻断。客户端收到 `SENSITIVE_DATA_BLOCKED` 后清除问题原文，只保留“已在本地阻断”的占位文本。

服务端审计只记录：

- `privacy_categories`；
- `privacy_action=BLOCKED_BEFORE_PROVIDER`；
- `redaction_applied=true`；
- question 哈希和长度。

不记录原问题、手机号、邮箱或支付凭证。

## 4. 成本审计

真实响应和审计记录 provider、model、prompt/completion/total tokens、provider latency、估算成本、`cost_status`、`answer_status`、`citation_support_passed` 和 `effective_answer`。

由于未取得 Dify 官方计费页或合同确认的模型单价，估算金额统一为 `null`，成本状态为 `COST_UNKNOWN`。审计仍不保存问题原文、个人信息或 API Key。

## 5. 服务端凭据

`.env.local` 位于阶段 3B 原型目录并被 Git 忽略。`.env.example` 只包含变量名和占位值。Dify Key 只在 `dify-adapter.mjs` 的服务端 Authorization Header 中使用。
