# 安全边界与 P0 门禁

## 1. 请求前置检查

BFF 依次检查：

1. `X-Demo-Role` 与请求体角色一致；
2. 租户固定为模拟租户；
3. 环境只允许当前 `candidate`；
4. question 非空且不超过 2000 字符；
5. 禁止 `api_key`、`secret`、`password`、`authorization` 等敏感字段；
6. 固定 TopK=3、混合检索、Rerank 和强制引用；
7. `Idempotency-Key` 为 16-128 字符。

自由文本和上下文值在 Dify 前执行隐私检查，命中手机号、邮箱、验证码、密码、支付凭证、完整序列号、身份证或详细地址时返回 `SENSITIVE_DATA_BLOCKED`。审计仅写类别、阻断动作、问题哈希和长度。

## 2. P0 信号

BFF 在调用 Dify 前识别以下信号：

- 冒烟、明火、火花、焦味或焦糊；
- 鼓包、电池膨胀、熔化、液体渗出或漏液；
- 进液后继续使用或充电；
- 异常发烫、烫手、明显烫伤、皮肤持续灼痛或不适；
- 接口烧痕、熔化或发热后继续充电；
- 已确认六条 P0 基线中的其他风险组合。

## 3. 固定安全动作

命中后立即返回：

1. 停止使用并停止充电；
2. 断开电源并隔离可燃物；
3. 提示明火、持续冒烟或人员不适时的应急条件；
4. 创建 R3 升级与安全/售后责任人转交；
5. 引用固定安全切片 `CHUNK-SAFE-STOP-01`。

响应记录 `provider_called=false`、`provider_request_id=null`，Dify 普通问答路径不会执行。P03 不展示普通 ADV，只有用户确认后才将 ASQ 标为安全暂停。

## 4. 已确认基线

阶段 4A 项目负责人签署记录确认：

- POC-S01；
- POC-S02；
- POC-S03；
- POC-S04；
- POC-K03；
- POC-E05。

本阶段端到端测试逐条验证六条均由 BFF 前置阻断。
