# 错误与超时处理

## 1. 归一化错误码

| 情况 | HTTP | error_code | 行为 |
| --- | ---: | --- | --- |
| 输入/敏感字段错误 | 422 | `VALIDATION_ERROR` | 不调用 Dify |
| 自由文本或上下文含个人信息/凭证 | 422 | `SENSITIVE_DATA_BLOCKED` | 在 Dify 前阻断并写脱敏审计 |
| 角色、租户、环境或 CORS 越界 | 401/403 | `UNAUTHORIZED` / `FORBIDDEN_SCOPE` | 不返回业务内容 |
| 同一幂等键不同请求 | 409 | `DUPLICATE_REQUEST` | 不覆盖原结果 |
| Dify 超时 | 504 | `RETRIEVAL_TIMEOUT` | 不返回缓存或部分回答 |
| Dify 网络/5xx | 502 | `PROVIDER_UNAVAILABLE` | 明确失败，允许重试 |
| Dify 429 | 429 | `RATE_LIMITED` | 返回可重试状态 |
| 无有效知识 | 200 | `NO_ANSWER` | 拒答或转人工 |
| 知识过期 | 200 | `KNOWLEDGE_EXPIRED` | 不用过期来源 |

## 2. 超时与重试

当前模板默认：

- `RAG_REQUEST_TIMEOUT_MS=45000`；
- `RAG_MAX_RETRIES=1`；
- 只对超时、网络错误、429 和 5xx 重试；
- 幂等响应只在完整成功后保存。

开发过程中第一次正式请求仍使用阶段 4A 的 8 秒配置，BFF 正确返回 `RETRIEVAL_TIMEOUT`，没有伪造成功。调整为 45 秒后真实请求正常完成。

这些耗时只用于当前原型验证，不构成生产 SLA。
