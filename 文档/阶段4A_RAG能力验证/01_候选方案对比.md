## 2. 为什么不能现在就选型

1. 当前环境没有 FastGPT、Dify 或 RAGFlow 的 API Key/Base URL；
2. 当前环境没有 Docker/WSL，无法启动官方依赖栈；
3. 三家官方文档都声称具备 RAG/API 能力，但本项目必须验证业务条件、引用支持、过期知识和 P0 安全；
4. 功能列表、代码规模和社区热度不能替代真实检索与回答结果；
5. 所以本轮供应商选择状态为“待真实对照实验”，而不是“已选定”。

## 3. 建议的最小比较顺序

1. Dify：优先申请 single-tenant 测试工作区与 Knowledge Base/App API，验证完整 RAG 和引用；
2. FastGPT：同步申请测试空间与 OpenAPI 凭据，使用完全相同的材料与配置复测；
3. RAGFlow：仅当 Dify/FastGPT 在表格切片、引用或元数据过滤上出现无法接受的问题时加入；
4. 每家仅先跑 `CFG-BASE`、`CFG-HYBRID`、`CFG-RERANK`，不一次展开全部参数；
5. 真实结果进入同一指标表，P0 失败具有一票否决权。

## 3.1 实际执行后的更新

- Dify Cloud 已完成 BASE、HYBRID、RERANK 和 TEST 专项真实实验；
- FastGPT 仍未获得测试凭据，因此不能宣称 Dify 在能力上优于 FastGPT；
- 当前决策是：Dify 作为已完成真实 PoC 的当前实施方案，FastGPT 保留为后续对照候选；
- 应用 API 在真实环境中稳定返回检索资源，但生成层没有稳定执行 P0 首段止损，最终采用必须有企业 BFF 安全门禁。
