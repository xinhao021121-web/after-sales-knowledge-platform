# 决策日志

## D-4B2A-001 Dataset API 与 App API 分离

- 日期：2026-10-25
- 决策：使用独立的 `RAG_DIFY_DATASET_API_KEY`。
- 原因：现有 App Key 不能调用 Dataset 管理接口；混用会扩大权限边界。

## D-4B2A-002 BFF 控制文件范围

- 日期：2026-10-25
- 决策：浏览器只能选择冻结 manifest 中的 `doc_id`，不能提交任意文件路径。
- 原因：防止路径穿越、误传非候选文件和无依据上传。

## D-4B2A-003 文档状态与索引状态分离

- 日期：2026-10-25
- 决策：分别保存 `document_status` 和 `provider_status`。
- 原因：BFF 任务生命周期与 Dify 解析/切片/索引生命周期不是同一状态机。

## D-4B2A-004 失败重试更新原文档

- 日期：2026-10-25
- 决策：已有 `provider_document_id` 时使用 `update-by-file`。
- 原因：避免重试产生重复文档，同时保留业务幂等键。

## D-4B2A-005 P10 质量门槛

- 日期：2026-10-25
- 决策：即使 17 条执行完成，只要核心来源或其他质量基线未达到，运行仍为 `FAILED`，不生成发布候选。
- 依据：2026-10-25 更新数据集后的真实运行核心来源 6/12、Recall@3 `0.5000`，仅 1 条模型型有效 `ANSWERED`。

## D-4B2A-006 成本状态

- 日期：2026-10-25
- 决策：未取得官方单价或合同前，所有成本金额为 `null`，状态为 `COST_UNKNOWN`。
- 禁止：把 Dify usage 中的 0 元解释为免费，或据此宣称某模型成本更低。

## D-4B2A-007 Scoped Key 健康检查

- 日期：2026-10-25
- 事实：Scoped Dataset Key 调用 `/datasets` 列表接口返回 403。
- 决策：健康检查改为 `/datasets/{CANDIDATE_DATASET_ID}`。
- 原因：这是 Dify 的权限范围语义，不需要为了健康检查扩大 Key 权限。
