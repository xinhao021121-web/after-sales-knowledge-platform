# 配置与证据边界

## 1. 实验定义

本阶段是“公开资料驱动的模拟企业项目”中的真实 Dify 生成模型对照，不代表 Apple 内部实验，也不使用真实客户数据。17 条任务来自阶段 4A 冻结评测集 `EVAL-RAG-POC-1.0.0`。

## 2. 配置冻结

| 项目 | CFG-RERANK-PRO | CFG-RERANK-FLASH |
| --- | --- | --- |
| 状态 | 不可变基线 | 4B-1 候选配置 |
| Dify App ID | `4da4b901-0f6e-4f35-b89e-8170d83bb7e0` | 同左 |

## 3. 证据边界

- Dify 服务 API 不返回当前已发布应用的全部模型配置，因此模型身份由 Dify Advanced Chat 已发布版本 `#9`、界面配置和 Git 忽略的服务端环境变量共同记录。
- 本阶段没有重新评测 TopK、切片、Rerank 或检索权重。Recall@3 与正确来源沿用阶段 4A 的 Pro 结果，并核对本轮实际返回的 Top3 文档顺序。
- E02/E03/E04 仍使用当前 CANDIDATE 应用提问；TEST 专用原始文档没有被合并进 CANDIDATE。
- 旧 Pro 的 17 个原始响应、`summary.json`、正式 `comparison.json` 与人工复核均未修改。输入锁记录其 SHA-256。
- 两轮温度、提示词和输入完全一致。模型文本有随机差异，因此结论基于两轮一致的关键动作，不声称逐字复现。

## 4. P0 调用顺序

当任务带 `p0=true` 时，实验 BFF 在执行任何 Dify 请求之前完成规则匹配，返回固定止损动作、R3 升级、证据引用和止损后追问。原始记录必须同时满足：

- `provider_called=false`
- `gate_order=BFF_BEFORE_DIFY`
- `answer_status=BLOCKED_SAFETY`

6 条 P0 分别是 POC-S01、S02、S03、S04、K03、E05。模型不能通过更温和的表达绕过 BFF 门禁，也不被要求承担 P0 自行兜底。

## 5. 凭据与数据

真实服务端配置位于 Git 忽略的 `阶段4A_RAG能力验证/.env.local`。提交物不包含 Base URL 凭据、API Key、Dify 会话标识或真实客户信息。实验只使用公开售后资料和模拟上下文。
