# 需求追踪矩阵说明

日期：2026-10-23  
机器可读矩阵：[02_需求追踪矩阵_V1.4.csv](02_需求追踪矩阵_V1.4.csv)

## 1. 覆盖

- 功能需求：30 条，`FR-001` 至 `FR-030`；
- 实施波次：`P0-W1`、`P0-W2`、`P0-W3` 及跨波需求；
- 每条需求都绑定业务原则、至少一条核心任务、核心对象、对象自身状态或跨对象事件、验收 ID 和风险错误码。

## 2. 字段

| 字段 | 含义 |
|---|---|
| `req_id` | 功能需求唯一编号 |
| `wave` | P0 实施波次 |
| `title` | 功能名称 |
| `business_source` | 对应业务原则 |
| `core_task_ids` | 对应的正式核心任务 |
| `objects` | 涉及的业务对象 |
| `state_transition` | 对应对象自身状态路径或跨对象事件 ID；跨对象事件详情见 [03_状态转换总表_V1.4.md](03_状态转换总表_V1.4.md) |
| `acceptance_ids` | GTW 或跨需求验收条件 |
| `error_codes` | 需要拦截或处理的 U 类错误 |
| `dependencies` | 前置功能或冻结基线 |

## 3. 追踪规则

- `FR-xxx` 不得只出现在标题或页面名中；
- 新增或删除需求必须更新本矩阵；
- `acceptance_ids` 必须能在 [04_核心任务GTW验收条件.md](04_核心任务GTW验收条件.md) 或 [05_异常与系统拦截附录.md](05_异常与系统拦截附录.md) 中找到；
- `core_task_ids` 只能使用阶段 1B 的 12 条人工确认任务；
- 只有页面、按钮或交互而没有业务来源的需求不得进入 PRD；
- 跨对象权限、审计和监控需求在矩阵中列出其作用到的关键状态；不得用“全局有效”代替状态追踪。
- 当前对象自身状态只能写同对象状态；`EV-01` 至 `EV-21` 表示独立跨对象事件，必须包含目标对象、目标初始状态、是否创建对象、幂等键和失败处理。
- P0 发布模型为一个 `REL` 绑定一个 `kb_version_id`；`REL_ACTIVE` 按租户、环境、业务域和 `knowledge_item_id` 唯一。业务域级批量快照属于 P1。
- `CASE` 与 KB 版本通过 `CASE_LINK(case_id, kb_version_id)` 形成 0..N 关联；REL 创建后补充 `rel_id`，无 CASE/LINK 不阻断正常知识首次发布。
- `CASE_LINK` 使用五态生命周期；不同知识条目可并行修复，同一 case+knowledge_item 同时最多一条活动 LINK。
- CASE 无 LINK 时仅允许双角色批准“无需知识修复”；有 LINK 时按每个知识条目最新 LINK 聚合关闭，部分 KB 发布不得提前关闭 CASE。
