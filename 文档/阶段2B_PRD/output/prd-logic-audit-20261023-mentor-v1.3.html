风险等级怎么理解？

阻断表示知识问题闭环无法唯一实现。 CASE_LINK 已有数据对象，却没有完整生命周期，因此无法作为可靠的业务关联。

阻断

CASE 状态推进和关闭条件无法唯一实现，可能提前关闭或永久卡住。

高风险

可能造成越权、错误发布或严重流程事故。

中风险

字段或边界缺失，可能造成返工和测试分歧。

低风险

局部表达或交付格式问题。

CASE_LINK 有对象、有唯一键，但没有创建和关闭事件

EV-08、EV-09、EV-11、EV-13、EV-18 依赖 CASE 关联，但没有任何事件创建或更新 CASE_LINK，也无法判断一个 CASE 需要满足多少个关联修复后才能关闭。

评审放行条件

定义 CASE_LINK 的状态、创建时点、更新时点、关闭条件和相关事件；补齐 CASE 关联多个 KB 的完整验收。

问题详情

PRD-001 CASE_LINK 关联对象缺少完整生命周期

阻断对象生命周期确定缺口
位置与证据
PRD 10 新增 CASE_LINK(case_id, kb_version_id)，并声明 CASE 与 KB 是 0..N 关系。但状态总表没有 CASE_LINK 状态和转换；EV-14 创建新 KB_DRAFT 时没有创建关联；EV-08 依赖“关联 CASE”，EV-11 关闭全部关联 CASE，EV-09 和 EV-13 又仍使用单数 CASE；EV-18 新建 CASE 时也没有说明是否关联受影响 KB。
漏洞说明
研发无法确定 CASE_LINK 何时产生、何时挂到 REL、何时失效。一个 CASE 关联多个待修复 KB 时，只要其中一个 KB 发布，EV-11 就可能关闭整个 CASE；反过来，如果关联没有创建，EV-08 会把关联数视为 0，导致 CASE 永远不被推进。
触发场景
CASE-01 需要修复 KB-A、KB-B → EV-14 创建两个 KB_DRAFT 但未创建 CASE_LINK → EVAL 通过后 EV-08 找不到 CASE → CASE-01 停留修复中；另一种场景：两 KB 都已关联 → KB-A 先发布 → EV-11 过早关闭 CASE-01，KB-B 尚未发布。
影响范围
CASE、KB、REL、EV-08/09/11/13/14/18、关闭门禁、发布证据和审计。
待确认问题
P0 是否允许一个 CASE 同时关联多个待修复 KB？CASE 关闭是否要求所有活动关联都完成发布或明确不发布？
最小修改建议
建议为 CASE_LINK 定义 LINK_OPEN、LINK_RELEASED、LINK_ABANDONED 三态；EV-14 创建 LINK_OPEN，EV-08 填充 rel_id，EV-11 只有在 CASE 的全部活动 LINK 均为 RELEASED 或 ABANDONED 时才关闭 CASE。EV-09、EV-13、EV-18 明确处理 0..N 个关联。
关联修改
PRD 10、11.1、FR-019/023/024/025、EV-08/09/11/13/14/18、AC-G-27/31、新增 CASE_LINK 验收、状态图。

PRD-002 ESC 关联字段没有进入核心对象定义

中风险字段一致性确定缺口
位置与证据
G-22、FR-013、EV-01 和 AC-G-29 都要求使用 previous_esc_id，但 PRD 第十章的 ESC 关键字段只列了 paused_from_state，没有列入 previous_esc_id。
漏洞说明
研发可能只实现状态转换，不持久化历史风险单关联，导致复发风险无法回溯。
触发场景
ESC-01 已关闭 → 客户再次报告风险 → 新建 ESC-02 → 系统没有 previous_esc_id 字段 → 无法关联同一客户和历史处置。
影响范围
风险复发、审计、案例关联和客户历史。
待确认问题
无；应将 previous_esc_id 补入 ESC 对象字段并标记可空唯一关联。
最小修改建议
在对象模型和字段校验中补齐 previous_esc_id，并验证其不产生循环和重复追溯。
关联修改
PRD 10、FR-013、EV-01、AC-G-29、追踪矩阵和状态图。

发现问题后，产品经理怎么处理

  1. 先定义 CASE_LINK 的生命周期和 CASE 关闭不变量。
  2. 再让所有 CASE 相关事件明确处理 0..N 关联。
  3. 最后补齐 ESC 字段和跨文件验收，重新执行全量检查。
