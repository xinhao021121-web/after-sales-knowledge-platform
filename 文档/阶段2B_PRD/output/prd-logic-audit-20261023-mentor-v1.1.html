问题详情

PRD-001 跨对象事件仍未覆盖两个核心闭环

阻断闭环断裂确定缺口
位置与证据
FR-024 和 CASE 状态表要求 EVAL 通过后进入 CASE_VERIFIED_PENDING_RELEASE，但 EV-08 的目标只有 KB 和 REL，没有 CASE。另，EV-07 会把来源失效的 ACTIVE REL 改为 REL_SUSPENDED，而 EV-12 只允许从 REL_ACTIVE 创建回滚候选，REL_SUSPENDED 没有回到待批准候选的路径。
漏洞说明
研发按事件表实现时，评测通过后 CASE 会一直停留在 REGRESSION_PENDING，REL 生效也无法执行 EV-11 关闭案例；来源失效后当前版本已经停用，却无法进入受控回滚，只能永久停用或私自改状态。
触发场景
修复 CASE → EVAL 通过 → EV-08 创建 REL → CASE 未变为 VERIFIED_PENDING_RELEASE；另：SRC 失效 → EV-07 停用 REL → 系统尝试回滚 → EV-12 前置条件不满足。
影响范围
CASE 闭环、EVAL 结果回流、REL 发布、来源故障恢复、回滚审批、审计与 GTW。
待确认问题
评测成功是否应在创建 REL 候选的同一原子事件中把关联 CASE 推进到待发布？停用版本是否允许创建回滚候选？
最小修改建议
扩展 EV-08，将关联 CASE 同步更新为 CASE_VERIFIED_PENDING_RELEASE；新增从 REL_SUSPENDED 创建新 REL_PENDING_APPROVAL 的回滚事件，或扩展 EV-12 的来源状态，并明确来源复验、审批和幂等键。
关联修改
FR-019、FR-021、FR-024、AC-K4-02、AC-G-03、AC-G-15、状态总表 EV-07/08/12、追踪矩阵 FR-019/021/024 行、状态图。

PRD-002 KB 不可变版本与退回草稿存在语义冲突

高风险版本冲突确定冲突
位置与证据
PRD 10.1 声明 KB 使用不可变版本；但状态表允许 KB_BUSINESS_REVIEW 和 KB_EVAL_PENDING 回到 KB_DRAFT，EV-09 也会把已进入评测的 KB 直接更新为 KB_DRAFT，而 KB_DRAFT 允许编辑事实和条件。
漏洞说明
若研发允许原草稿继续编辑，会改写已有审核/评测证据对应的内容；若坚持不可变，则状态转换无法执行。两种解释都会产生不同版本和审计结果。
触发场景
KB-v3 完成业务审核 → EVAL 失败 → EV-09 把 KB-v3 设为 DRAFT → 知识运营修改正文 → 原 EVAL 记录仍指向 KB-v3，但内容已经变化。
影响范围
KB 版本、业务审核、EVAL 证据、CASE 修复、发布候选和审计。
待确认问题
版本不可变从创建时开始，还是从提交业务审核时开始？
最小修改建议
建议提交业务审核后冻结 KB 内容；评测失败将当前 KB 置为只读失败态，并创建新的 KB 草稿版本。若允许评审前编辑，则修正“所有 KB 版本不可变”的表述并明确冻结时点。
关联修改
PRD 10.1、KB 状态表、EV-09、FR-017/019/023、AC-K3-02、AC-G-12、PRD 决策记录。

PRD-003 新增 EV-16 未进入统一幂等验收

高风险验收遗漏确定缺口
位置与证据
状态总表新增 EV-16，用于激活新 REL 并把同作用域旧 ACTIVE 替代；但 AC-G-26 只要求覆盖 EV-01 至 EV-15。
漏洞说明
测试按 AC-G-26 执行时不会验证 EV-16 的重复提交和原子性。重复激活可能造成两个 REL_ACTIVE、旧版本未替代或审计缺失。
触发场景
客户端重试“发布”请求 → EV-16 被调用两次 → 第二次再次创建替代/审计或返回不一致状态。
影响范围
REL_ACTIVE 唯一性、替代、发布审计、回滚准备和发布验收。
待确认问题
EV-16 是否与其余跨对象事件使用同一幂等和原子性验收？
最小修改建议
将 AC-G-26 覆盖范围改为 EV-01 至 EV-16，并增加“重复激活新 REL 不产生第二个 ACTIVE”的明确断言。
关联修改
AC-G-26、AC-G-22、FR-020、08 验收记录、需求追踪矩阵。

PRD-004 文档中存在三个局部编号或计数不一致

低风险文档一致性表达问题
位置与证据
PD-005 仍写 SRC 为“六态”，V1.1 状态表实际为七态并包含 SRC_REGISTERED；PRD 存在两个 13.3 章节；EVAL_PASSED 状态行写作“E-08”，事件表写作“EV-08”。
漏洞说明
不影响状态规则本身，但会造成目录跳转、交叉引用和自动检查误判。
触发场景
研发或测试按“六态”实现，遗漏登记态；文档链接到 13.3 时无法确定是发布回滚测试还是在线监控。
影响范围
文档可读性、追踪效率和自动检查。
待确认问题
无；应统一为七态、13.3/13.4 和 EV-08。
最小修改建议
统一状态计数、章节编号和事件前缀，并重新生成目录或复检报告。
关联修改
PD-005、PRD 13.3/13.4、状态总表 EVAL_PASSED 行、复检报告。

发现问题后，产品经理怎么处理

  1. 先补齐 EVAL→CASE 和 SUSPENDED→回滚候选两个跨对象事件。
  2. 再明确 KB 内容冻结时点，确保审核与评测证据指向不可变内容。
  3. 最后统一所有事件验收和文档编号，重新执行全量检查。
