# 状态转换总表 V1.4

日期：2026-10-23
核心规则：本对象只进入自身状态；创建或更新其他对象只能通过跨对象事件。一个 REL 仅绑定一个 `kb_version_id`；同一 `case_id + knowledge_item_id` 最多一条活动 LINK。

> 当前版本 V1.4；历史 V1.1、V1.2、V1.3 保留用于审计。

## 1. 自身状态转换

### 1.1 售后咨询任务 `ASQ`（10 状态）

| 当前状态 | 负责人 | 进入条件 | 允许动作 | 下一自身状态 | 失败/回滚 |
|---|---|---|---|---|---|
| `ASQ_NEW` | 一线客服/售后专员 | 客户诉求已建立 | 记录诉求、初筛风险 | `ASQ_CONTEXT_PENDING` / `ASQ_ASSESSING` / `ASQ_PAUSED` / `ASQ_CANCELLED` | 重复请求按幂等键返回原任务 |
| `ASQ_CONTEXT_PENDING` | 一线客服 | 商品、渠道、时间或状态不足 | 追问、补证、创建新 `CTX` 版本 | `ASQ_ASSESSING` / `ASQ_PAUSED` / `ASQ_CANCELLED` | 无响应保持待补证 |
| `ASQ_ASSESSING` | 一线/售后 | 上下文达到最低判断条件 | 检索证据、条件判断、识别冲突 | `ASQ_ADVICE_PENDING` / `ASQ_HANDOFF_PENDING` / `ASQ_PAUSED` | 证据不足回 `ASQ_CONTEXT_PENDING` |
| `ASQ_ADVICE_PENDING` | 一线/售后 | 建议与证据已生成 | 核对、驳回、采用、转交 | `ASQ_RESPONDED` / `ASQ_ASSESSING` / `ASQ_HANDOFF_PENDING` / `ASQ_PAUSED` | 驳回回 `ASQ_ASSESSING` |
| `ASQ_HANDOFF_PENDING` | 售后/主管 | 需要专业判断或渠道裁决 | 补材料、指定责任人 | `ASQ_RESPONDED` / `ASQ_RESOLVED` / `ASQ_ASSESSING` / `ASQ_PAUSED` | 无接收人保持待办 |
| `ASQ_RESPONDED` | 一线/售后 | 已人工确认并发送 | 记录反馈、补证、安排售后 | `ASQ_RESOLVED` / `ASQ_ASSESSING` / `ASQ_HANDOFF_PENDING` / `ASQ_PAUSED` | 错误答复创建问题案例 |
| `ASQ_PAUSED` | 当前处理角色 | 来源对象发生风险并已创建 `ESC` | 查看风险状态；不得发送普通建议 | `ASQ_PAUSED` 等待跨对象事件 | `paused_from_state` 无效时恢复为 `ASQ_ASSESSING` |
| `ASQ_RESOLVED` | 一线/售后 | 客户完成/接受下一步并有记录 | 补结果、关闭、复盘 | `ASQ_CLOSED` / `ASQ_ASSESSING` / `ASQ_PAUSED` | 重复联系回 `ASQ_ASSESSING` |
| `ASQ_CLOSED` | 一线/主管 | 无未关闭 ESC，审计完整 | 只读、引用评测 | 终态（可新建后继 ASQ） | 新证据创建新任务版本 |
| `ASQ_CANCELLED` | 一线/主管 | 重复、误建、撤回或超范围 | 记录原因和审计 | 终态 | 误取消新建/重开并留证 |

### 1.2 风险升级单 `ESC`（7 状态）

| 当前状态 | 负责人 | 进入条件 | 允许动作 | 下一自身状态 | 失败/回滚 |
|---|---|---|---|---|---|
| `ESC_CANDIDATE` | 任意处理角色 | 风险信号已登记 | 暂停普通建议、必要时追问 | `ESC_CONFIRMED` / `ESC_DISMISSED` | 信息不足保持候选 |
| `ESC_CONFIRMED` | 客服主管；R3 安全/法务 | 风险等级确认 | 止损、事件记录 | `ESC_MITIGATING` / `ESC_ESCALATED` | 不得进入普通售后判断 |
| `ESC_MITIGATING` | 一线/售后 | 客户仍需执行止损 | 停止使用/充电、隔离 | `ESC_ESCALATED` / `ESC_MONITORING` | 客户拒绝执行则 `ESC_ESCALATED` |
| `ESC_ESCALATED` | 主管/售后/安全责任人 | 需要专业处置 | 转售后、安全、法务或应急 | `ESC_MONITORING` / `ESC_CLOSED` | 无接收人保持升级待办 |
| `ESC_MONITORING` | 售后/安全责任人 | 已转交，等待结果 | 记录进展、补证、重估 | `ESC_CLOSED` | 新风险必须新建 ESC |
| `ESC_CLOSED` | R2 主管；R3 安全/法务 | 止损、转交、结果、审计完整 | 复盘、关闭 | 终态 | 复发创建新 ESC，旧单不可改写 |
| `ESC_DISMISSED` | 主管/安全责任人 | 证据证明不构成 R2/R3 | 记录排除依据 | 终态；跨对象事件 EV-02 恢复 ASQ | 新风险创建新 ESC |

`ESC` 必填字段：`paused_from_state`（发生风险时的 `ASQ_*` 自身状态）和可空 `previous_esc_id`（只允许指向同客户已关闭或已排除的旧 ESC，每个旧单最多一个后继，写入后不可改）。
`ESC_CLOSED` 和 `ESC_DISMISSED` 都是终态；新风险创建新的 `ESC_CANDIDATE`，不得把旧终态改为 `ESC_REOPENED`。
`previous_esc_id` 必须通过自引用、目标终态、同客户和全链循环校验；非法关系拒绝创建并写失败审计。

### 1.3 知识来源 `SRC`（7 状态）

| 当前状态 | 负责人 | 进入条件 | 允许动作 | 下一自身状态 | 失败/回滚 |
|---|---|---|---|---|---|

| `SRC_ACTIVE` | 知识运营 | 五项激活条件全部通过 | 被 KB 引用、接受到期/变更监控 | `SRC_REVIEW_REQUIRED` / `SRC_EXPIRED` / `SRC_SUPERSEDED` / `SRC_WITHDRAWN` / `SRC_UNAVAILABLE` | 来源变化触发跨对象阻断事件 |
| `SRC_REVIEW_REQUIRED` | 知识运营 | 临近到期、官方变更或冲突 | 复核原文和范围 | `SRC_ACTIVE` / `SRC_EXPIRED` / `SRC_WITHDRAWN` / `SRC_UNAVAILABLE` | 未复核不得用于新发布 |
| `SRC_EXPIRED` | 知识运营 | 有效期结束或规则失效 | 阻断新引用、创建新来源候选 | `SRC_SUPERSEDED` / `SRC_WITHDRAWN` | 不直接恢复活跃 |
| `SRC_SUPERSEDED` | 知识运营 | 新来源版本完成核验 | 保留历史、触发关联 KB 复核 | 终态 | 新来源回滚只能回到待复核 |
| `SRC_WITHDRAWN` | 法务/业务/来源方发起；知识运营登记 | 官方撤回或无效声明 | 阻断新引用和新发布 | 终态 | 新建来源版本 |
| `SRC_UNAVAILABLE` | 知识运营/系统检测 | 证据不可访问 | 保留最后核验信息，阻断新发布 | `SRC_REVIEW_REQUIRED` / `SRC_WITHDRAWN` | 不自动恢复活跃 |

`SRC_ACTIVE` 必须同时满足：可访问、标题已核验、范围明确、有效期明确、责任人明确。

### 1.5 问题案例 `CASE`（9 状态）

| 当前状态 | 负责人 | 进入条件 | 允许动作 | 下一自身状态 | 失败/回滚 |
|---|---|---|---|---|---|
| `CASE_OPEN` | 客服/售后/主管/评测 | 发现错误、缺口、冲突或风险 | 保存原对象、证据和版本；允许暂无可修复 LINK | `CASE_TRIAGED` / `CASE_DEFERRED` | 证据不足保持；无 LINK 只能按无需知识修复门禁关闭 |
| `CASE_TRIAGED` | 知识运营 | 类型和责任角色明确 | 分派、补证 | `CASE_EVIDENCE_READY` / `CASE_FIXING` / `CASE_DEFERRED` | 分诊错误重分诊 |
| `CASE_EVIDENCE_READY` | 知识运营 | 原始证据完整 | 分析根因、制定修复 | `CASE_FIXING` / `CASE_DEFERRED` | 证据缺失退回 |
| `CASE_FIXING` | 知识运营/业务负责人 | 修复方案确认，或分诊确认无需知识修复 | EV-14 创建 KB_DRAFT 和 LINK_OPEN；不同知识条目可并行；无 LINK 时申请双角色批准关闭 | `CASE_REGRESSION_PENDING` / `CASE_CLOSED` | 同一知识条目已有活动 LINK 时不重复创建；无 LINK 关闭使用幂等键 `CASE:{id}:CLOSE_NO_FIX:{approval_id}`；无批准时保持修复 |
| `CASE_REGRESSION_PENDING` | AI 评测/知识运营 | 修复候选已提交 | 执行回归 | `CASE_VERIFIED_PENDING_RELEASE` / `CASE_FIXING` | 失败回修复 |
| `CASE_VERIFIED_PENDING_RELEASE` | AI 评测/主管 | 无 OPEN/FAILED，至少一条 LINK_PENDING_RELEASE | 等待相关 REL 生效或明确弃置 | `CASE_CLOSED` / `CASE_FIXING` | 部分发布但有其他待发布时保持；失败/来源失效回修复 |
| `CASE_CLOSED` | 知识运营/主管 | 每个知识条目最新 LINK 为 RELEASED/ABANDONED 且无活动 LINK，或经无需知识修复双角色批准且无 LINK | 只读、引用评测和 LINK 聚合快照 | 终态 | 新问题进入 `CASE_REOPENED`；不得因部分 KB 发布关闭 |
| `CASE_REOPENED` | 任意责任角色 | 重复问题、发布异常或新证据 | 保留旧记录、重新评估；已有后继 LINK_OPEN 时进入修复 | `CASE_TRIAGED` / `CASE_EVIDENCE_READY` / `CASE_FIXING` | 不覆盖旧案例 |
| `CASE_DEFERRED` | 主管/知识运营 | 依赖不足 | 记录原因、责任人和复审条件 | `CASE_TRIAGED` / `CASE_REGRESSION_PENDING` | 超期需主管确认 |

### 1.6 案例关联 `CASE_LINK`（5 状态）

| 当前状态 | 负责人 | 进入条件 | 允许动作 | 下一自身状态 | 失败/回滚 |
|---|---|---|---|---|---|
| `LINK_OPEN` | 知识运营 | EV-14 创建 KB_DRAFT；EV-13/18 创建后继链路 | 提交审核和回归 | `LINK_PENDING_RELEASE` / `LINK_FAILED` / `LINK_ABANDONED` | 同一 case+knowledge_item 已有活动 LINK 时拒绝新开 |
| `LINK_PENDING_RELEASE` | AI 评测/主管 | EV-08 评测通过并绑定 rel_id | 等待 REL 生效或明确弃置 | `LINK_RELEASED` / `LINK_FAILED` / `LINK_ABANDONED` | 发布失败保持或失败；不关闭 CASE |
| `LINK_RELEASED` | 知识运营 | EV-11 对应 REL_ACTIVE | 只读，作为历史证据和后继源 | 终态 | 回滚不改写，创建后继 LINK_OPEN |
| `LINK_ABANDONED` | 主管 + 业务/渠道负责人 | EV-19 明确不发布且批准完整 | 只读 | 终态 | 批准或审计失败保持原状态 |
| `LINK_FAILED` | AI 评测/知识运营 | EV-09/EV-18/EV-20 失败 | 保留失败证据；创建后继修复或申请弃置 | `LINK_ABANDONED` | 不得直接关闭 CASE；后继修复由 EV-14 新建 LINK_OPEN |

`CASE_LINK` 唯一键为 `case_id + kb_version_id`。不同 `knowledge_item_id` 可并行修复，但同一 `case_id + knowledge_item_id` 同时最多一条 `LINK_OPEN` 或 `LINK_PENDING_RELEASE`。CASE 关闭时按每个知识条目的最新 LINK 聚合；任一活动 LINK 存在时不得关闭。

## 2. 跨对象事件

`当前对象自身下一状态`只允许填写同对象状态；其他对象必须单列目标和初始状态。

| ID | 来源对象/允许状态 | 事件 | 触发条件 | 当前对象自身下一状态 | 目标对象 | 目标初始/更新状态 | 新建对象 | 幂等键 | 审计与失败处理 |
|---|---|---|---|---|---|---|---|---|---|
| EV-01 | ASQ：NEW/CONTEXT_PENDING/ASSESSING/ADVICE_PENDING/HANDOFF_PENDING/RESPONDED/RESOLVED | 检测到 R2/R3 | 风险信号成立；可选旧 ESC 必须为已关闭或已排除的同客户终态 | `ASQ_PAUSED`，保存 `paused_from_state` | ESC | `ESC_CANDIDATE`，写入可空 `previous_esc_id`；自引用、非终态目标或循环链拒绝 | 是 | `ASQ:{id}:RISK:{risk_signal_id}` | 写 ASQ/ESC/AUD；重复同值幂等，不同值或非法链拒绝；创建失败则 ASQ 保持暂停并重试 |
| EV-02 | ESC：DISMISSED | 排除风险并恢复咨询 | 证据证明不构成 R2/R3；CTX/EVD/ADV 重校验 | 保持 `ESC_DISMISSED` | ASQ | `paused_from_state`；重校验失败则 `ASQ_ASSESSING` | 否 | `ESC:{id}:DISMISS_RESUME` | 写 ESC/ASQ/AUD；重校验失败不得直接发送旧建议 |
| EV-03 | ESC：CLOSED | 风险处置结束 | 风险关闭且 ASQ 仍暂停 | 保持 `ESC_CLOSED` | ASQ | `ASQ_ASSESSING`，重新生成或确认 ADV | 否 | `ESC:{id}:CLOSED_RESUME` | 写 ESC/ASQ/AUD；写入失败时保持 ASQ_PAUSED，不恢复已失效 ADV，重试同键 |
| EV-04 | SRC：EXPIRED/WITHDRAWN/UNAVAILABLE | 来源失效影响 KB | 存在关联 KB | 保持当前来源终态 | KB | `KB_SOURCE_BLOCKED` | 否 | `SRC:{id}:v{n}:KB_BLOCK` | 写 SRC/KB/AUD；可重试，不自动改写历史 KB |

## 3. 跨对象事件不变量

- 来源对象只写自身状态；目标对象的创建/更新由事件执行。
- 跨对象事件必须原子更新来源对象状态、目标对象状态和审计；
- 失败时不得留下“目标已创建但来源未暂停”或“REL 已停用但回滚候选不存在”的不可解释状态；
- 幂等键重复时必须返回原对象和原结果；
- `EVAL_PASSED`、`EVAL_FAILED`、`ESC_DISMISSED` 等来源状态在事件完成后保持不变；
- 历史 `REL`、历史 `KB` 和历史 `SRC` 不因新事件改写；
- 同一 `tenant_id + environment_id + business_domain_id + knowledge_item_id` 只能有一个 `REL_ACTIVE`。
- 一个 REL 只绑定一个 `kb_version_id`；CASE 通过 `CASE_LINK(case_id, kb_version_id)` 形成 0..N 关联。
- `LINK_OPEN` 和 `LINK_PENDING_RELEASE` 是活动状态；`LINK_RELEASED`、`LINK_ABANDONED` 是成功/明确终止终态；`LINK_FAILED` 是失败保留态，只能由 EV-19 明确弃置或通过新建后继 LINK 继续修复。
- 同一 `case_id + knowledge_item_id` 同时最多一条活动 LINK；不同知识条目可并行。
- CASE 只有在无活动 LINK 且每个知识条目的最新 LINK 为 `LINK_RELEASED/ABANDONED` 时才可关闭；最新 LINK 为 `LINK_FAILED` 时进入 `CASE_FIXING`。
- 历史 `LINK_RELEASED` 不因 EV-13/EV-18 改写；继续修复必须创建 `LINK_OPEN` 后继，并用 `previous_link_id` 追溯。
- `REL_REJECTED` 不得与 `LINK_PENDING_RELEASE` 或 `CASE_VERIFIED_PENDING_RELEASE` 共存；由 EV-20 原子回退到 LINK_FAILED/CASE_FIXING。
- `KB_REJECTED/KB_WITHDRAWN` 不得与仍活动的同 KB LINK 共存；由 EV-21 原子回退到 LINK_FAILED/CASE_FIXING。
