# 角色、权限与责任边界

版本：V0.1  
日期：2026-10-22

## 1. 角色地图

| 角色 | 主要责任 | 不属于该角色的责任 |
|---|---|---|
| 消费者 | 提出售后诉求、提供必要信息、确认结果 | 不作内部责任判断 |
| 一线客服 | 识别诉求、创建咨询任务、补齐基础上下文、发送已确认建议或发起转交 | 不单独批准复杂规则、保修责任、渠道兜底或高风险关闭 |
| 售后专员 | 判断故障、退换修、检测、保外服务和历史维修关系 | 不批准业务政策或法务结论 |
| 客服主管 | 处理风险升级、渠道冲突、投诉和交付质量 | 不替代安全/法务专业判断 |
| 业务/渠道负责人 | 确认业务口径、渠道责任、适用范围和例外 | 不代替 AI 评测证明质量 |
| 知识运营 | 整理来源、维护知识版本、处理问题案例、执行发布流程 | 不能单独批准自己提交的知识，不能代替业务负责人确认政策 |
| AI 评测人员 | 维护评测任务、标注、回归和发布前质量证据 | 不能批准业务政策，不能单独发布 |
| 法务/安全责任人 | 对法律、渠道约定和安全高风险问题提供专业裁决 | 不承担日常客服运营 |
| 系统管理员 | 配置权限、集成和技术操作，执行经批准的发布/回滚 | 不能绕过业务审核、评测或审计直接发布 |

## 3. 强制职责分离

### 3.1 知识提交与审批

- 知识提交人和批准人不能是同一操作主体；
- 知识运营可提交自己维护的知识，但必须由业务/渠道负责人独立批准；
- 若业务/渠道负责人参与起草，批准人必须更换为更高层级的独立责任人；
- 系统必须在提交、批准和发布动作中校验身份，不能只提供操作提示。

### 3.2 安全风险不能绕过

- 任意角色触发 R2/R3 后，普通建议进入暂停状态；
- R2 至少需要客服主管确认；
- R3 需要安全/法务责任人或其明确授权角色确认；
- 一线客服不能关闭 R2/R3；
- 知识运营、AI 评测和系统管理员不能把风险单降级为普通咨询。

### 3.3 知识运营与业务口径

- 知识运营负责来源、结构、版本和维护；
- 业务/渠道负责人拥有政策和责任范围批准权；
- 对跨渠道冲突，必须由相关渠道负责人确认，不能由知识运营自行折中；
- 法务/安全角色在必要时提供专业意见，不替代业务负责人承担口径责任。

### 3.4 AI 评测与业务批准

- AI 评测人员可以证明“测试是否通过”，不能证明“政策是否正确”；
- 评测失败时阻止发布；
- 评测通过也不自动授予发布权；
- 业务批准与评测结果必须同时存在，才可进入发布准备。

### 3.5 系统管理员边界

- 管理员只能配置身份、连接和技术操作；
- 管理员不得查看不必要的客户内容，不得修改业务结论；
- 管理员不得直接绕过审核和评测发布知识；
- 紧急情况下可执行已授权的停用或回滚，但必须自动生成高危审计记录；
- 恢复被紧急停用的版本必须经业务/渠道负责人和 AI 评测人员重新确认。

## 4. 责任分配原则

- 内容事实由知识运营组织，业务/渠道负责人批准；
- 客户建议由一级或售后角色确认发送；
- R2/R3 风险由安全链路负责关闭；
- 评测证据由 AI 评测人员提供；
- 发布运营责任由客服主管承担；
- 技术要求与系统可用性由管理员承担；
- 消费者不接受内部责任转移，所有内部转交都必须有可追踪对象。
