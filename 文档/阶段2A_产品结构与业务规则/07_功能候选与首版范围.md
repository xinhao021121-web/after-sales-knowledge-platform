# 产品功能候选与首版范围

版本：V0.1  
日期：2026-10-22

## 1. 范围原则

功能候选只从已确认的 12 条核心任务、三组业务原则和 11 个核心对象推导，不新增竞品功能。阶段 2A 只定义产品能力，不定义页面。

## 2. P0：首版必须存在

| 能力 | 解决的问题 | 支撑核心任务 | 对应对象 |
|---|---|---|---|
| 咨询任务建立与诉求分类 | 统一承载客户售后请求 | 全部 12 条 | `ASQ` |
| 上下文快照与缺口识别 | 避免缺少商品、渠道、时间和状态即作判断 | 全部 12 条 | `CTX` |
| 风险前置识别与持续复检 | 防止普通流程漏掉 R2/R3 | CORE-S1 至 S4，以及全部规则任务 | `ESC`、`ASQ` |
| 有效证据引用 | 阻止过期、不适用或冲突知识进入建议 | 全部 12 条 | `SRC`、`KB`、`EVD` |
| 条件性处理建议 | 明确动作、例外、承诺边界和转交 | 全部 12 条 | `ADV` |
| 必须追问字段提示 | 让系统在条件不足时主动补证 | 全部 12 条 | `CTX`、`ADV` |

| 审计与不可变记录 | 追溯证据、建议、审批和状态 | 全部 12 条 | `AUD` |

### 2.1 P0 实施波次

P0 范围不缩减。分波只定义依赖顺序和每波的验收出口，最终生产使用前必须完成全部 P0。

| 波次 | P0 能力切片 | 依赖 | 验收出口 |
|---|---|---|---|
| P0-W1 核心辅助与安全最小闭环 | 咨询任务、上下文快照、风险门禁、风险升级单、有效证据展示、条件性建议、人工确认、审计；使用冻结的核心知识集合 | 阶段 1B 的 12 条正式核心任务 | 规则与安全任务可在人工确认下完成答复/转交；所有 R2/R3 强制进入安全流程；无越权发送 |
| P0-W2 来源、知识与问题案例 | 知识来源状态、知识版本、业务审核、问题案例、职责分离和发布前检查 | P0-W1；来源与知识维护角色确认 | 来源和知识状态完整；提交人不能自批；问题案例有责任人、证据和修复记录 |
| P0-W3 评测、发布与回归 | 评测任务、发布版本、发布确认、在线监控、停用/回滚和回归闭环 | P0-W2；人工确认核心任务与来源门禁 | 评测失败不能发布；案例在评测通过待发布时不能提前关闭；发布异常可停用并回滚 |

`[规则]` R2/R3 强制安全分支从 P0-W1 开始生效，不因分波延后。所有 P0 波次完成后，才能将产品视为具备正式生产条件。

## 3. P1：后续扩展

| 能力 | 延后原因 |
|---|---|
| 消费者端低风险自助问答 | 需在人工辅助质量稳定后验证 |
| 订单、物流、CRM 自动上下文获取 | 依赖外部系统授权和真实字段确认 |
| 自动创建退换、维修或补偿动作 | 风险高，需要更明确的授权与审计 |
| 多品牌、多语言和经销商门户 | 会扩大规则和权限复杂度 |
| 客服质检和培训建议 | 依赖稳定结果标签 |
| 运营趋势分析 | 当前没有真实运营数据 |
| 来源自动同步与变更监控 | 需先验证来源治理流程 |
| 多模态识别 | 需验证图像在安全与身份场景中的边界 |

## 4. 暂不设计

- 高度自动化的工作台页面；
- 客服聊天 UI 或消费者 App；
- 模型、向量库、检索参数和 Agent 架构；
- 自动退款、赔偿、保修或法律判断；
- 医疗诊断；
- 通用企业搜索；
- 多租户计费、插件市场和分润；
- 用文档数量或问答次数衡量成功。

## 5. 首版最小闭环

`客户问题 -> 咨询任务 -> 上下文 -> 证据 -> 建议/风险升级 -> 人工处理 -> 问题案例 -> 评测/发布 -> 审计`

只有这个闭环完整，首版才具备可验证的产品结构。
